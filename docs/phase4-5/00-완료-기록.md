# Phase 4.5 완료 기록: s4 살펴보기

상태: **구현 완료** (실제 사용자 확인과 파일럿 조정이 남음)

## 왜 이 단계가 생겼나

주 사용자를 "여러 프로젝트를 병행하는 사원"으로 좁히고, 차별점을 **빠뜨리지 않고 한곳에 모아 한눈에 보는 것**으로 정했다. PRD에 없던 기능(프로젝트 화면, 빠짐 점검, 데이터 비교, 시각화)을 안정화(Phase 5)보다 먼저 만들었다. 항목 이름·단위 같은 데이터 구조가 여기서 정해지므로, 백업 형식을 한 번에 확정하기 위해서다. 샘플과 예시는 필름 제품 개발(하드코팅 HC-300, AG 방현, 접이식 유연 코팅)로 바꿨다.

## 만든 것

**프로젝트** `/projects`, `/projects/:id`
- 목록: 프로젝트마다 실험 수, 상태별 개수, 전체 단계 진행률, 확인할 것 개수, 최근 활동. 프로젝트 만들기.
- 현황: 상태별 막대, **빠진 것 한눈에**, 타임라인(시작~완료 막대, 오늘 표시선), 최근 실험. 이름·목표 수정(자동 저장).
- 데이터: 프로젝트의 모든 실험을 항목별로 한 표에 모음. 같은 이름의 조건·결과는 한 열, 조건이 결과보다 앞, 시작한 날짜순. 이상치(▲), 빈 값(—), 항목 없음(·), 단위 확인 표시. **CSV 내보내기**(엑셀용 BOM).
- 분석: 가로축·세로축(조건 또는 결과)을 골라 **산점도**와 상관계수(풀어 쓴 해석과 "원인은 아님" 안내), **실험 순서별 추세**(중앙값선), **이상치 후보** 목록. 점을 누르면 그 실험으로 이동.

**빠짐 점검** (`services/analysis.ts`, 화면 밖에서도 테스트 가능한 순수 함수)
- 결과 없이 완료 / 비어 있는 결과 / 미완료 단계가 남은 완료
- 오래 멈춘 실험: 진행 7일, 준비 14일
- 빠진 항목: 같은 프로젝트 실험의 절반 이상(최소 2건)이 쓰는 조건·결과가 이 실험에 없음 (결과는 완료한 실험만)
- 단위 불일치
- 이상치 후보: 수정 z 점수(중앙값과 MAD). 값이 5건 미만이면 판단하지 않고, 값 대부분이 같은 경우는 기준을 더 엄격하게
- 홈의 "놓친 것"에 모든 프로젝트의 빠진 것을 심각한 순서로, 프로젝트 이름과 함께 표시

**입력 단계의 빠짐 방지**
- 새 실험에서 프로젝트를 고르면 **마지막 실험 이어받기**(기본 켬): 절차, 조건 값, 결과 항목 이름·단위를 가져오고 결과 값은 비운다. 프로젝트 화면의 "+ 이 프로젝트에 새 실험"에서도 같은 프로젝트로 시작.
- **항목 이름 자동 완성**: 조건·결과 탭과 수행 모드에서 같은 프로젝트에서 쓴 이름을 제안하고, 이름이 같으면 단위를 채운다.

**차트**: 외부 라이브러리 없이 SVG로 직접 구현(산점도, 추세선, 타임라인, 상태 막대). 차트마다 스크린 리더용 요약, 점과 막대는 키보드로 열 수 있고, 색에 글자(개수, 이름)를 함께 쓴다.

**저장소·데이터**
- `duplicate`가 결과 항목 이름·단위를 남기도록 바뀜(계약 테스트 반영).
- 시연 데이터 `seedDemo`: 3개 프로젝트 17건. 몇 주에 걸친 이력과 일부러 심어 둔 빠짐 5건, 이상치 1건(헤이즈 3.9%). 개발 모드의 홈 빈 화면에서 "데모 데이터 넣기".
- 작은 고정 샘플 `seedSample`(테스트용)도 같은 도메인으로 교체.

## 확인한 결과

- `npm run check`: 린트, 타입 검사, 테스트 13개 파일 **141개 모두 통과**
- 분석 함수 단위 테스트 + 시연 데이터 통합 테스트: 심어 둔 빠짐 5건과 이상치 1건이 정확히 나오고, 정상 실험 8건에는 아무것도 나오지 않음
- 프로젝트 목록·현황·데이터·분석, 홈의 놓친 것, 이어받기, 자동 완성 통합 테스트
- 실제 브라우저에서 홈의 "놓친 것", 프로젝트 현황, 분석 화면(산점도·경향선) 확인. 콘솔 오류 없음.

## 알려진 한계

- **"확인함" 처리가 없다**: 의도적으로 건너뛴 항목도 빠진 것으로 계속 나온다. 파일럿에서 오탐이 거슬리는지 보고 만든다.
- **점검 기준은 가정이다**: 진행 7일·준비 14일, 절반 이상이 쓰는 항목, 이상치 기준이 현장에 맞는지는 모른다. 오탐을 기록해 조정한다. 이상치는 어디까지나 후보다.
- **이름이 달라지면 열이 갈라진다**: 자동 완성으로 줄였지만 "건조온도"와 "건조 온도"는 띄어쓰기를 무시해 같은 항목으로 묶어도, "Temp" 같은 다른 표기는 합치지 못한다.
- **통계는 단순하다**: 상관계수와 직선뿐이다. 실험 수가 적으면 우연일 수 있다고 화면에 안내한다. 프로젝트별 목표 사양(예: 투과율 90% 이상)과의 비교는 아직 없다.
- 와이어프레임(`docs/design/wireframes.html`)에는 s4 화면이 아직 없다.
- 린트 경고 10건(동작 영향 없음): 컴포넌트와 훅을 한 파일에서 내보냄, effect 안의 setState, 렌더 중 `Date` 사용.
