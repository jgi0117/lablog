# Phase 3 완료 기록: s1 모으기

상태: **구현 완료, 검증 2건 남음** (아래 "남은 것" 참고)

## 만든 것

**실험 만들기** `/experiments/new`
- 제목만 필수(비면 안내). 목적, 프로젝트(그 자리에서 새 프로젝트 생성 가능), 태그(쉼표 구분).
- 만들면 준비 상태로 절차 편집 화면으로 이동.

**실험 상세** `/experiments/:id` (공통 틀 + 탭 3개)
- 개요: 제목·목적·담당자·프로젝트·태그를 바꾸면 자동 저장(저장 표시). 진행 현황, 시작·완료·수정 시각. 완료하기, 다시 열기(재개), 삭제(휴지통 + 되돌리기).
- 절차: 단계 추가·수정(입력을 멈추면 저장)·삭제(되돌리기)·순서 변경, 여러 줄 붙여넣기(번호 접두어 자동 제거).
- 조건·결과: 이름-값-단위 행, 단위 자동 완성, 삭제 되돌리기, 숫자가 아닌 값·평소와 크게 다른 값은 막지 않고 경고(E7). 완료 처리 영역: 미완료 단계와 빈 결과를 알리고 "나중에 입력하고 완료" 허용(E3, E8).

**수행 모드** `/experiments/:id/run` (앱 셸 없는 전체 화면)
- 진입하면 준비 → 진행으로 바꾸고 시작 시각 기록. 아직 체크하지 않은 첫 단계를 현재 단계로 표시.
- 체크 줄 전체가 눌림. 체크하면 즉시 저장하고 진행률 갱신, 5초 되돌리기 토스트(E2). 건너뛰기 허용.
- 현재 단계 아래: 조건·결과 값 입력과 단계 메모(자동 저장, 저장 표시). 방향키로 단계 이동. 이전 / 완료하고 다음 단계 / 마지막에는 수행 완료.
- 오른쪽에 지금까지 입력한 조건·결과. 화면 꺼짐 방지(지원하는 브라우저에서). 완료된 실험은 안내와 다시 열기.
- 달라진 점 기록은 s3에서 만들며, 버튼은 비활성으로 자리만 확정.

**홈**: 진행 중 실험(남은 단계 수 포함)과 최근 실험을 카드로 표시. 카드를 누르면 상태에 맞는 화면으로 이동.

**공통**: StatusBadge, ProgressBar, ExperimentCard(Phase 4에서 목록에도 사용), `useExperimentData`(상세 데이터 로딩), `useDebouncedSave`(자동 저장, 실패 시 다시 시도, 화면을 떠날 때 마저 저장), 서비스 계층(`experimentService`: 생성·상태 전이·단계 추가, `validation`, `text`).

## 확인한 결과

- `npm run check`: 린트, 타입 검사, 테스트 9개 파일 **80개 모두 통과**
- Journey 1 통합 테스트 통과: 홈 → 새 실험 → 절차 붙여넣기 → 수행 모드(준비→진행) → 메모·조건 입력 → 되돌리기 → 수행 완료 → 완료(저장소에 상태·시각·태그·조건 값 확인)
- 완료 경고(E3, E8), 삭제 되돌리기(E2·E5), 값 경고(E7), 자동 저장·저장 실패 재시도(E1)의 테스트 포함
- 실제 브라우저(개발 서버, 1194×834)에서 수행 모드를 열어 체크 → 진행률 5/9 · 56%, 메모 자동 저장("저장됨"), 콘솔 오류 없음 확인

## 알려진 사항

- "완료하고 다음 단계" 버튼에는 되돌리기 토스트가 없다. 단계 줄을 눌러 해제할 수 있다. 필요하면 추가.

- 린트 경고 5건(동작 영향 없음): 컴포넌트와 훅을 한 파일에서 내보냄 3건, effect 안의 setState 2건(`useExperimentData`, `RunPage`).
