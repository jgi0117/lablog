# 고객 요구 특성과 사용성 개편

상태: **구현 완료.** 신제품 개발은 "고객이 요청한 특성을 만족하는 조건을 찾는 일"이다. 그래서 프로젝트가 고객 요구를 들고 있고, 모든 화면이 그 요구를 기준으로 "지금 어디까지 왔나, 다음에 무엇을 할까"를 알려 주도록 바꿨다.

## 무엇이 불편했나

- 프로젝트에 "고객이 무엇을 요구했는가"를 적을 곳이 없어서, 실험 결과가 좋은지 나쁜지를 사람이 머릿속으로 비교해야 했다.
- 새 실험을 만들 때마다 무엇을 재야 하는지(결과 항목)를 직접 만들어야 했고, 빠뜨려도 알 수 없었다.
- 홈은 실험 목록 중심이라 "프로젝트별로 고객 요구에 가까워졌는가"가 보이지 않았다.

## 고객 요구 특성

프로젝트에 **고객(또는 요청 부서)**와 **요구 특성** 목록을 둔다. 요구 하나는 다음으로 이루어진다.

| 항목 | 설명 |
|---|---|
| 항목 이름·단위 | 실험의 같은 이름 항목(조건 또는 결과)과 맞춘다(띄어쓰기·대소문자는 무시). 예) 압축강도, MPa |
| 조건 | 이상(≥), 이하(≤), 범위(최소~최대), 목표값±허용 |
| 적용 조건(선택) | "이 조건일 때만". 예) 재령 28일일 때의 압축강도. 실험의 조건 값이 정확히 같을 때만 판정하고 나머지는 "해당 없음" |
| 중요도 | 필수(고객이 꼭 요구) / 있으면 좋음 |

원가나 사용량 제한처럼 **조건 항목에 거는 요구**도 된다(예: 시멘트 ≤ 400 kg/m³).

## 판정 방식 (`services/requirements.ts`)

- **실험 단위**: 한 실험이 한 요구를 만족하는가(만족 / 미달 / 값 없음 / 해당 없음).
- **배합 단위**: 신제품 개발에서 고객이 보는 것은 "이 배합이 7일 20 MPa 이상이고 28일 40 MPa 이상인가"이다. 그래서 적용 조건(재령 등)을 뺀 나머지 조건 값이 모두 같은 실험들을 한 **배합**으로 묶어, 같은 배합의 7일·28일 시험을 함께 본다. 필수 요구를 모두 만족한 배합이 있으면 프로젝트는 "요구 달성"이다. 희망 요구는 달성 여부에 영향을 주지 않는다.
- **아직 달성하지 못했으면** 필수 요구를 가장 많이 만족하고 모자란 정도(목표에 대한 비율)가 가장 작은 배합을 "가장 가까운 배합"으로 알려 주고, 무엇이 얼마나 모자란지 적는다. 값이 아직 없는 요구는 "측정값이 없습니다"로 알린다.
- 한계값이 빠졌거나 범위가 뒤집힌 요구는 저장하지 않는다(입력 줄에 이유를 보여 준다).

## 화면

- **프로젝트 > 고객 요구 탭**: 고객과 요구를 입력한다. 고칠 때마다 자동 저장되고, 아래 달성 현황이 바로 바뀐다. 덜 쓴 줄은 이유를 보여 주고 저장하지 않는다.
- **프로젝트 현황 맨 위**: "고객 요구 달성 현황". 한 문장 결론(달성한 배합 몇 개 / 가장 가까운 배합과 모자란 요구), 요구별 표(상태, 만족/판정 건수, 가장 가까운 값과 그 실험). 요구가 없으면 입력으로 안내하고, 실험이 하나도 없는 프로젝트에서도 요구 입력 안내가 먼저 보인다.
- **새 실험**: 프로젝트를 고르면 제목을 "프로젝트 이름 #번호"로 제안한다(비워 두면 그 제목으로 만든다). **요구에 맞춰 측정할 항목(결과 항목과 적용 조건)을 빈칸으로 미리 만들어** 준다. 이어받기나 템플릿으로 시작해도 빠진 요구 항목만 더한다.
- **실험 개요·조건·결과·수행 모드**: "고객 요구 판정" 줄에 이 실험이 필수 요구 몇 개를 만족하는지, 항목별 만족·미달·값 없음을 보여 준다. 조건·결과 탭의 입력 줄 옆에는 "✓ 요구 만족 / ✗ 요구 미달"이 붙고 값을 고치면 바뀐다.
- **데이터 표(프로젝트·전체)**: 요구를 만족한 칸은 초록, 미달한 칸은 붉은 바탕(글자로도 "요구 만족/미달"을 읽는다). "고객 요구" 거르기로 필수 요구를 모두 만족한 실험이나 미달이 있는 실험만 볼 수 있다.
- **분석**: 요구를 달성한 실험과 못 미친 실험을 나눠, 어떤 조건이 달성 여부와 가장 관련 있는지와 달성한 실험들의 조건 범위(대부분 10~90 백분위)를 "한눈에 읽기"에 더한다("다음 실험은 이 범위에서 시작해 보세요"). 각 집단에 실험이 3건 이상일 때만 나온다.
- **홈**: 맨 위에 "+ 새 실험 / + 새 프로젝트 / 전체 데이터 보기"와 **프로젝트 현황** 카드. 카드마다 고객, 요구 달성 상태(요구 달성 / 진행 중 / 측정 전), 필수 요구 달성 수, 실험 수와 **지금 가장 도움이 될 다음 행동**(요구 입력하기, 가장 가까운 배합에서 부족한 요구, 달성한 배합 수)을 보여 준다.

## 예시 데이터

예시 프로젝트 4개에 가상의 고객(이름 끝에 "(예시)")과 요구를 넣었다.
- SM-00(한빛건설 구조팀): 28일 압축강도 ≥ 30 MPa, 7일 ≥ 20 MPa(필수), 시멘트 ≤ 400 kg/m³(희망)
- ES-30(그린인프라공사): 28일 ≥ 50 MPa, 고로슬래그 ≥ 120 kg/m³, 시멘트 ≤ 300 kg/m³(모두 필수)
- LF-20(한솔플랜트 설비팀): 56일 ≥ 55 MPa, 28일 ≥ 45 MPa(필수), 플라이애시 ≥ 80 kg/m³(희망)
- HB-50(미래전력 토목팀): 28일 ≥ 80 MPa(아직 아무도 못 넘는 도전 목표), 물 ≤ 170 kg/m³(필수), 고성능 감수제 ≤ 12 kg/m³(희망)

수치는 지어낸 예시이며 실제 고객 요구가 아니다. 전체 데이터(1,030건)에서 SM·ES·LF는 달성한 배합이 있고, HB는 "진행 중"으로 가장 가까운 배합이 표시된다.
이미 예시를 넣어 둔 브라우저는(구성 2) 예시 프로젝트를 고치지 않았다면 다음에 열 때 자동으로 고객·요구가 반영된다.

## 알아 둘 점

- 요구는 숫자 항목에만 건다. 문자 값(예: 외관 양호)은 판정하지 않는다.
- 단위는 변환하지 않는다. 요구와 실험의 단위가 다르면(예: MPa와 kgf/cm²) 값만 비교하므로 먼저 통일해야 한다.
- 같은 이름의 조건과 결과가 함께 있으면 결과를 우선한다.
- 백업 파일 형식은 그대로 2다. 프로젝트에 고객·요구가 선택 항목으로 더해졌고, 이전 파일은 그대로 가져온다. 알아볼 수 없는 요구는 파일 전체를 거부하지 않고 그 요구만 버린다.
