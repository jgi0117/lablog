# 데이터 허브와 통계 분석

상태: **구현 완료.** 이 서비스의 강점은 실험을 빠뜨리지 않고 모으는 데서 그치지 않고, **모인 데이터를 그대로 통계와 머신러닝에 쓸 수 있다**는 점이다. 이 문서는 그 부분이 무엇을 하고 어디까지 믿어도 되는지 적는다.

## 왜 만들었나

예시 데이터를 공개 데이터 전체(1,030건)로 늘려 보니 아쉬운 점이 드러났다.
1. 프로젝트 데이터 표가 12건 남짓을 가정한 모양이라 실험이 많아지면 끝까지 볼 수 없었다.
2. 분석 화면이 산점도 하나와 추세뿐이라 "그래서 무엇이 결과를 움직이는가"를 알려 주지 못했다.
3. 프로젝트마다 따로 볼 수만 있고, 모든 실험의 데이터를 한곳에서 보거나 다른 도구로 가져갈 방법이 없었다.

## 만든 것

**데이터 허브** (`/data`, 왼쪽 메뉴 "데이터"): 모든 프로젝트의 실험을 실험 한 줄씩의 표로 합친다. 같은 이름의 조건·결과는 프로젝트가 달라도 한 열이다. 세 탭이 있다.
- **표**: 검색, 상태·프로젝트 필터, 머리글을 눌러 정렬(값이 없는 칸은 항상 맨 아래), 열 고르기(조건만/결과만/하나씩), 한 번에 보기 25·50·100·전체, 머리글과 실험 열 고정. 프로젝트의 데이터 탭도 같은 표를 쓴다.
- **분석**: 아래 "분석이 보여 주는 것". 범위를 모든 프로젝트 또는 한 프로젝트로 고른다.
- **내보내기**: 파일 5종과 파이썬 예시 코드.

**분석이 보여 주는 것** (프로젝트 분석 탭과 허브의 분석 탭이 같은 화면):
| 구역 | 내용 | 방법 |
|---|---|---|
| 한눈에 읽기 | 근거(r, p, 실험 수)를 붙인 문장 | 아래 구역들의 요약 |
| 영향 주는 조건 | 결과마다 조건별 상관을 막대와 표로 | 피어슨 r, 스피어먼 순위상관, p-값, 다중회귀(표준화 β) |
| 조건 값별 비교 | 재령처럼 몇 가지 값으로 반복하는 조건으로 나눠 평균±표준편차 | 일원분산분석(F, p), 효과 크기 η² |
| 조건과 결과의 관계 | 산점도와 경향선 | 단순회귀 |
| 분포 | 히스토그램, 평균·중앙값 | 스터지스 규칙 구간 |
| 상관 행렬 | 숫자 항목 사이 모든 쌍 | 쌍마다 피어슨 r |
| 순서 추세, 상·하위 실험 | 시작 순서별 값, 높은 5건·낮은 5건 | |
| 요약 통계 | 항목마다 평균, 표준편차, 사분위, 결측, 이상치 | 엑셀 QUARTILE.INC와 같은 분위수 |

**내보내기 파일**
- **분석용 CSV**(넓은 형식, 숫자만): 실험 한 건이 한 줄, 조건·결과가 열. 숫자가 아닌 값과 빈 칸은 빈칸, BOM 없음. 파이썬·R·모델용.
- **엑셀용 CSV**: 입력한 값 그대로, BOM을 붙여 한글이 깨지지 않게.
- **긴 형식 CSV**(tidy): 값 하나가 한 줄(실험, 구분, 항목, 값, 숫자값, 단위). 그룹별 통계용.
- **JSON**: 실험마다 조건·결과를 이름으로 묶음.
- **데이터 사전**: 열마다 구분, 단위, 단위가 섞였는지, 개수, 결측, 평균·표준편차·범위, 이상치 수.
- 내보내기 화면이 먼저 결측 비율과 단위 혼합을 알려 준다. 단위는 바꾸지 않고 그대로 내보내므로, 섞여 있으면 사용자가 먼저 통일해야 한다.
- 모든 파일은 이 기기 안에서 만들어지고 어디로도 전송되지 않는다.

## 어디까지 믿어도 되는가

- **계산은 검증했다.** p-값은 외부 라이브러리 없이 직접 구현했고(불완전 베타 함수), 교과서 값(r=0.7746에서 p=0.124, F=13·자유도(2,6)에서 p=0.0066, t 분포 임계값)과 맞는지 단위 테스트로 확인한다.
- **p-값은 근사다.** 정규성과 독립을 가정하고, 실험이 적으면 참고용이다. 실험이 20건 미만이면 화면이 그렇게 알린다.
- **여러 번 비교하면 우연히 유의해 보이는 것이 섞인다.** 조건이 여럿이면 일부 ★은 우연일 수 있다. 중요한 조건은 다른 조건을 고정한 실험으로 다시 확인한다고 화면에 적어 두었다.
- **상관은 원인이 아니다.** 재료를 함께 늘리는 배합처럼 조건끼리 같이 움직이면 각각의 영향을 가르기 어렵다. 그래서 단독 상관(r)과 "다른 조건을 함께 고려한 영향(β)"을 나란히 보여 주고, 단독으로만 유의한 조건은 따로 알린다. 조건 사이에 완전한 종속(같은 정보)이 있으면 회귀를 풀지 않는다.
- **직선이 아닌 관계는 순위상관이 알려 준다.** 예: 콘크리트의 재령은 처음에 강도가 빨리 늘고 완만해지는 곡선이라 r(0.32)보다 순위상관(0.59)이 훨씬 크다. 그러면 "곡선에 가까운 관계일 수 있습니다"라고 알린다.
- **합치면 흐려진다.** 성격이 다른 프로젝트를 모두 합치면 경향이 섞인다. 분석 탭은 프로젝트별로도 보라고 안내한다.

## 예시 데이터로 확인한 것

공개 콘크리트 데이터(1,030건)에서 알려진 지식과 맞는 결과가 나온다(시멘트가 많을수록, 물이 적을수록, 재령이 길수록 강도가 높음). 에코슬래그 프로젝트에서 시멘트 r=0.67, 재령별 강도 평균 3일 21 → 91일 70 MPa(η²=0.52), 다중회귀 R²=0.63. 같은 데이터로 단위 테스트가 이 결과들을 확인한다.

## 머신러닝에 쓰려면

1. 데이터 > 내보내기에서 범위를 고르고 **분석용 CSV**와 **데이터 사전**을 받는다.
2. 사전에서 단위가 섞인 열이 없는지, 결측이 많은 열이 없는지 본다.
3. 화면의 "예시 코드"로 pandas에서 읽는다(결과가 비어 있는 실험은 학습에서 뺀다).
4. 진행·준비 중인 실험은 결과가 비어 있으니 완료한 실험만 쓰는 것이 안전하다.

## 예시 데이터는 전체 1,030건

- 처음 여는 브라우저(데이터 없음)에는 공개 데이터 전체가 들어간다(프로젝트 SM 232, ES 334, LF 239, HB 225건). Chromium에서 약 2~4초.
- 예전 구성(소규모)의 예시만 들어 있는 브라우저는 **직접 만든 기록이 없을 때에 한해** 새 구성으로 바뀐다(`lablog:example-seeded` 값이 `seeded:2`가 아니면). 직접 만든 기록이 있으면 건드리지 않는다.
- 시험은 숫자가 고정된 "고른 200건" 구성을 쓴다(`VITE_EXAMPLE_SET=curated`). 실제 앱의 기본은 전체이고, 별도 서버(first-run 시험)가 이 기본을 확인한다.
- 이상치 판단: 재령처럼 값이 몇 가지 수준(20개 이하이고 실험 수의 1/4 이하)으로 정해진 조건은 실험이 30건 이상이면 이상치로 보지 않는다(365일은 오류가 아니라 설계한 값). 전체 데이터에서도 이상치 후보가 연속 값(물, 시멘트 등)에만 남는다.
- 프로젝트 개요의 타임라인은 실험이 많으면 가장 최근 30건만 그린다.

## 남은 것

- 단위 자동 변환(지금은 섞여 있다고 알리기만 한다).
- 조건 값에 로그를 씌운 분석, 상호작용 항, 교차 검증 같은 모델링은 하지 않는다. 앱은 탐색과 준비까지 맡고 모델링은 내보낸 파일로 다른 도구에서 한다.
- 범주형 조건(문자, 예: 기재 종류)은 아직 분석에 넣지 않는다. 숫자로 읽히는 값만 쓴다.
