# Phase 4 완료 기록: s2 찾기

상태: **구현 완료** (첨부는 보류, 실제 사용자 확인 1건 남음)

## 만든 것

**실험 목록** `/experiments`
- 카드 목록(진행률, 남은 단계), 12개씩 페이지 나눔(이전·다음, "13–24 / 30").
- 필터: 상태 칩(전체·준비·진행·완료), 프로젝트, 태그, 기간(최근 7·30·90일, 마지막 수정 기준). 정렬: 최근 수정순(기본)·이름순·시작일순.
- 필터와 정렬, 페이지는 주소(`?status=&project=&tag=&period=&sort=&page=`)에 담긴다. 주소가 비어 있으면 마지막에 쓴 필터를 복원한다(기기 안 저장). "필터 초기화" 버튼.
- 빈 상태: 실험이 없을 때 / 조건에 맞는 실험이 없을 때를 구분. 휴지통 개수와 링크.

**통합 검색** `/search?q=`
- 제목·목적·태그·단계·메모·조건·결과를 한 번에 검색. 띄어쓰기·대소문자 무시, 부분 일치.
- 결과마다 일치 위치(제목, 단계 V, 메모, 조건, 결과)와 문구를 보여 주고 일치한 부분을 강조. 긴 글은 일치 위치 주변만 잘라서 표시.
- 위치별 칩(전체·제목·태그·단계·조건·결과, 개수 포함), 프로젝트·기간 필터. "4건 · 0.03초" 표시.
- 결과 없음(E4): 철자가 비슷한 낱말 제안(편집 거리), 필터 해제, 새 실험 만들기.
- 상단 검색창은 검색 화면에서 현재 검색어를 보여 준다. Ctrl K로 포커스.

**휴지통** `/trash`
- 삭제한 실험 목록(삭제 시각, 영구 삭제까지 남은 일수), 복원, 영구 삭제(확인창, 되돌릴 수 없음 안내).
- 앱을 열 때 보관 기간(30일)이 지난 항목을 자동으로 영구 삭제.

**저장소**
- `ExperimentRepository.purge(id)` 추가(휴지통의 실험만). 계약 테스트 추가.
- 검색 색인(`data/local/searchIndex.ts`): 실험마다 글자를 한 번만 정규화해 메모리에 두고, 생성·수정·삭제된 실험만 다시 만든다(Dexie 훅으로 감지, 통째 가져오기는 전체 무효화). 계약 테스트에 "수정·삭제 뒤에도 최신" 케이스 추가.

## 확인한 결과

- `npm run check`: 린트, 타입 검사, 테스트 11개 파일 **112개 모두 통과** (계약 테스트 28개, 목록·검색·휴지통·Journey 2 통합 테스트 포함)
- **검색 성능**(실험 500건·단계 4,000개, 테스트용 가짜 IndexedDB): 처음 검색 29ms, 이후 3ms. 목표(2초 이내)를 크게 밑돈다. 실제 브라우저에서는 샘플 5건에서 "4건 · 0.03초".
- Journey 2 통합 테스트: 홈 → 검색 → 프로젝트 필터 → 결과 눌러 실험 열기. KR1 기준(10초 이내)을 테스트에서 단언.
- 실제 브라우저에서 검색 결과, 강조, 필터 칩, 목록 필터 주소 반영, 휴지통 화면 확인. 콘솔 오류 없음.

## 알려진 사항

- 검색 색인은 브라우저를 새로 열면 처음 한 번 전체를 읽어 다시 만든다. 현재 규모에서는 수십 ms지만, 수천 건이 되면 다시 측정한다.
- 검색은 부분 일치(띄어쓰기 무시)만 지원한다. 초성 검색, 어간 처리 등은 지원하지 않는다. 실제 검색어 패턴을 보고 판단한다.
- 린트 경고 5건(동작 영향 없음): 컴포넌트와 훅을 한 파일에서 내보냄 3건, effect 안의 setState 2건(`useExperimentData`, `RunPage`, `SearchPage`).
