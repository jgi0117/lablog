# Supabase 설정과 데이터 이전 가이드

앱 쪽 준비(서버 저장소, 로그인, 이전 마법사, 시험)는 끝났습니다. 아래는 **사용자가 직접 해야 하는 부분**입니다. 계정과 키는 본인만 만들 수 있고, 코드나 대화에 붙여 넣을 필요가 없습니다.
순서대로 하면 30분 안에 끝납니다.

## 1. Supabase 프로젝트 만들기

1. https://supabase.com 에 가입하고 **New project**를 누릅니다.
2. 이름은 `lablog`, 지역(Region)은 **Northeast Asia (Seoul)** 를 고릅니다. 데이터베이스 비밀번호는 비밀번호 관리자에 저장해 두세요(앱에는 쓰이지 않습니다).
3. 프로젝트가 만들어질 때까지 1~2분 기다립니다.

> 운영과 시험을 나누려면 프로젝트를 두 개(`lablog`, `lablog-test`) 만드세요. 3번의 시험은 반드시 시험 프로젝트에서만 돌립니다(시험이 데이터를 지웁니다).

## 2. 테이블 만들기 (SQL 적용)

1. 왼쪽 메뉴 **SQL Editor → New query**를 엽니다.
2. 이 저장소의 `supabase/migrations/20261020000000_init.sql` 파일 내용 전체를 붙여 넣고 **Run**을 누릅니다.
3. 같은 방법으로 `supabase/migrations/20261020000100_profiles.sql`도 실행합니다(프로필 표와 가입 시 자동 생성 트리거).
4. `Success. No rows returned`가 나오면 됩니다. 다시 실행해도 안전합니다.
5. **Table Editor**에 `profiles`, `projects`, `experiments`, `steps`, `data_items`, `templates`, `deviations`가 보이고, 각 표에 **RLS enabled** 표시가 있는지 확인합니다.

표 구조와 보안 설계는 `erd.md`에 있습니다.

## 3. 로그인 설정

**Authentication → Providers → Email**에서:
- Email 공급자가 켜져 있는지 확인합니다.
- 혼자 쓰고 메일 확인 단계를 건너뛰고 싶으면 **Confirm email**을 끕니다(켜 두면 계정을 만든 뒤 확인 메일의 링크를 눌러야 로그인됩니다).

**내 계정 만들고 가입 닫기**(개인용 설계, `erd.md`의 "로그인 설계"):
1. **Authentication → Users → Add user**로 내 이메일과 비밀번호를 만듭니다(**Auto Confirm User** 체크).
2. **Authentication → Sign In / Providers**에서 **Allow new users to sign up**을 끕니다.
3. 앱 로그인 화면에는 "계정 만들기" 버튼이 보이지 않습니다(`VITE_ALLOW_SIGNUP=true`일 때만 보임).

**Authentication → URL Configuration**에서(이메일 링크 로그인용):
- **Site URL**: 개발 중이면 `http://localhost:5173`, 배포했으면 배포 주소(예: `https://jgi0117.github.io/lablog/`).
- **Redirect URLs**에 위 주소들을 더합니다.

## 4. 앱에 접속 정보 넣기

1. **Project Settings → API**에서 **Project URL**과 **공개용 키**(`anon` 또는 `publishable` 키)를 복사합니다.
   - ⚠️ `service_role` 키(또는 `sb_secret_…`)는 **절대 넣지 마세요.** 모든 보안(RLS)을 우회하는 키입니다. 앱은 이 키가 들어 있으면 시작하지 않고 알려 줍니다.
2. `app/.env.local` 파일을 만들고 다음을 채웁니다(이 파일은 git에 올라가지 않습니다).

```bash
VITE_DATA_BACKEND=supabase
VITE_SUPABASE_URL=https://프로젝트-id.supabase.co
VITE_SUPABASE_ANON_KEY=공개용-키
```

3. 개발 서버를 다시 시작하고 http://localhost:5173 을 엽니다. 로그인 화면이 나옵니다.
4. 3번에서 만든 이메일과 비밀번호로 로그인합니다. 비밀번호를 잊으면 "이메일 링크로 로그인" 후 설정에서 새 비밀번호를 정합니다.

로컬 저장소로 돌아가려면 `VITE_DATA_BACKEND=local`로 바꾸고 다시 시작하면 됩니다(서버 데이터는 그대로 남습니다).

## 5. 기존 데이터를 클라우드로 옮기기

기존에 로컬 저장소로 쓰던 **같은 브라우저, 같은 주소(`http://localhost:5173`)** 로 들어와서 하세요(브라우저 저장소는 주소마다 따로입니다).

1. 로그인하면 위쪽에 "아직 서버로 옮기지 않은 기록이 N개 있습니다" 안내가 뜹니다. **클라우드로 이전**을 누릅니다(또는 설정 → 저장 위치).
2. 건수 미리보기(로컬 vs 서버)를 확인하고 **백업 파일 받고 N개 이전하기**를 누릅니다.
   - 먼저 로컬 백업 파일이 내려받아집니다. 안전하게 보관하세요.
   - 프로젝트 → 실험 → 단계 → 조건·결과 → 달라진 점 → 템플릿 순서로 올라갑니다.
   - 끝나면 서버에서 다시 읽어 모든 행이 들어갔는지 확인한 결과(건수 비교 표)가 나옵니다.
3. 중간에 멈추거나 실패해도 **다시 누르면 이어서** 올라갑니다(같은 id는 중복되지 않습니다).
4. 서버에서 잘 보이는지 확인한 뒤, 원하면 **로컬 데이터 지우기**로 이 브라우저의 사본을 지웁니다. 로컬은 자동으로 지워지지 않습니다.

다른 기기의 로컬 데이터도 같은 방법으로 옮깁니다(그 기기에서 같은 계정으로 로그인 → 이전).

> 로컬 백업 파일(JSON)만 있는 경우: 서버 저장소로 로그인한 뒤 설정 → "백업 파일 가져오기"로 올려도 됩니다.

## 6. 진짜 서버에서 시험 돌리기 (선택, 시험 프로젝트에서만)

계약 테스트와 보안(RLS) 침투 시험을 진짜 Supabase에서 돌립니다. 시험용 계정 두 개(A, B)를 만들어 두세요.

```bash
cd app
# Windows PowerShell 예시: $env:이름="값" 으로 설정한 뒤
#   SUPABASE_TEST_URL, SUPABASE_TEST_ANON_KEY,
#   SUPABASE_TEST_EMAIL, SUPABASE_TEST_PASSWORD   (계정 A)
#   SUPABASE_TEST_EMAIL2, SUPABASE_TEST_PASSWORD2 (계정 B)
npm run test:supabase
```

- 서버 저장소가 로컬 저장소와 같은 계약(38개)을 지키는지 확인합니다.
- B가 A의 데이터를 읽거나 고치거나 지울 수 없는지, 로그인하지 않은 사용자가 아무것도 못 보는지, 남의 실험에 단계를 붙일 수 없는지 확인합니다.
- 환경 변수가 없으면 이 시험은 자동으로 건너뜁니다(평소 `npm run check`에 영향 없음).

## 7. GitHub Pages 배포에서 서버 저장소 쓰기

저장소 **Settings → Secrets and variables → Actions → Variables**에 세 개를 추가하면 배포 빌드가 서버 저장소로 만들어집니다(공개용 키라서 Variables에 넣어도 됩니다).

| 이름 | 값 |
|---|---|
| `VITE_DATA_BACKEND` | `supabase` |
| `VITE_SUPABASE_URL` | Project URL |
| `VITE_SUPABASE_ANON_KEY` | 공개용 키 |

없으면 로컬 저장소 빌드가 됩니다. 배포 주소를 3번의 Site URL과 Redirect URLs에 넣는 것을 잊지 마세요.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| "서버 저장소 설정이 필요합니다" 화면 | `.env.local`의 두 값이 비어 있습니다. 채우고 개발 서버를 다시 시작하세요 |
| "서버에 표가 없습니다" | 2번 SQL을 적용하지 않았거나 다른 프로젝트에 적용했습니다 |
| "권한이 없습니다" | 로그인이 풀렸습니다. 다시 로그인하세요. 계속되면 2번 SQL의 RLS 정책이 적용됐는지 확인하세요 |
| 로그인이 안 됩니다 | 3번의 Confirm email 설정과 Site URL을 확인하세요 |
| 이전 마법사에 "옮길 로컬 데이터가 없습니다" | 다른 주소(포트)로 열었습니다. 예전에 쓰던 주소로 들어오세요 |
| 이전 후 건수가 다릅니다 | 건수 비교 표의 "서버에 없는 행"을 확인하고 다시 이전을 누르세요 |
