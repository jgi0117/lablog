# Phase 2 완료 기록: 기반 구축

## 한 일

**저장소 계층**
- `app/src/data/local/` IndexedDB(Dexie) 구현. 스키마 v1(projects, experiments, steps, dataItems)과 인덱스.
- 모든 저장소 메서드를 구현하고 `backend.contract.ts` 계약 테스트 23개를 모두 통과시켰다. Phase 9의 Supabase 구현도 같은 테스트를 통과해야 한다.
- `data/index.ts`가 `VITE_DATA_BACKEND`(local | supabase)로 구현을 고른다. 지금은 local만 있다.
- 저장 오류는 `StorageError`(quota, blocked)로 바꿔 던진다.
- 같은 밀리초에 저장해도 `updatedAt` 정렬이 흔들리지 않게 시각이 항상 증가하도록 했다(`nowIso`).

**앱 뼈대**
- 라우팅: IA의 URL과 1:1 (`/`, `/experiments`, `/experiments/new`, `/experiments/:id`, `/steps`, `/data`, `/search`, `/templates`, `/trash`, `/settings`, `*`). 수행 모드는 `/experiments/:id/run`으로 앱 셸 밖 전체 화면.
- 앱 셸: 왼쪽 메뉴(860px 이하에서는 아래), 상단 전역 검색(Ctrl K), + 새 실험.
- 공통 컴포넌트: EmptyState, SaveIndicator(저장됨/저장 중/실패), ConfirmDialog(Esc, 위험 동작은 취소에 포커스), Toast(되돌리기, 5초).
- 엔틱 토큰을 적용한 전역 스타일(`styles/global.css`).
- 홈은 저장소를 읽어 진행 중 실험을 보여 주는 최소 화면. 개발 모드에서만 "샘플 데이터 넣기" 버튼이 보인다.
- 아직 만들지 않은 화면은 `PlaceholderPage`로 어느 Phase에서 만드는지 표시한다.

**개발 환경**
- 샘플 데이터(`data/seed.ts`): 실험 5건과 대량 데이터 생성 함수.
- CI(`.github/workflows/ci.yml`): 푸시와 PR마다 린트, 타입 검사, 테스트, 빌드.

## 확인한 결과

- `npm run check`: 린트, 타입 검사, 테스트 5개 파일 48개 모두 통과 (경고 2건은 아래 참고)
- `npm run build` 성공 (JS 약 370KB, gzip 118KB)
- 실제 브라우저(개발 서버)에서 샘플 데이터를 넣으면 IndexedDB에 실험 5, 단계 22, 조건·결과 12, 프로젝트 3건이 저장되고 홈에 진행 중 2건이 표시됨. 콘솔 오류 없음.
- 좁은 화면에서 메뉴가 아래로 내려가는 것을 확인.

## 알려진 사항

- 린트 경고 2건: `BackendContext.tsx`, `Toast.tsx`가 컴포넌트와 훅을 한 파일에서 함께 내보낸다. 동작에는 영향이 없고, 훅을 별도 파일로 나누면 사라진다.
- 목록과 검색은 데이터를 읽어 메모리에서 거르고 정렬한다. 실험 수백 건에서는 충분하며, 느려지면 Phase 4~5에서 MiniSearch 색인을 붙인다.
- 화면 캡처는 한 번 시간 초과가 있었고, 이후 텍스트·저장소 확인과 한 장의 캡처로 대신 확인했다.
- E2E(Playwright)는 아직 없다. Phase 3에서 첫 시나리오와 함께 추가한다.
