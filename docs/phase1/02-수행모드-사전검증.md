# 수행 모드 사전 검증

목적: 코드를 만들기 전에 수행 모드가 실험대에서 쓸 만한지 연구원 2~3명에게 확인한다. 이 화면이 제품의 핵심이라 틀리면 되돌리기 비싸다.

## 준비물

- 시안: `docs/design/wireframes.html`의 "수행 모드"와 `docs/design/design-drafts.html`의 엔틱 스타일
- 태블릿 또는 노트북 (실제 쓸 기기와 가까운 것). 시안을 화면에 띄워 둔다.
- 장갑 (참여자가 평소 쓰는 것), 종이와 펜
- 측정: 손목시계 또는 타이머

## 진행 (참여자당 15분)

1. **설명 없이 보여 주기 (2분)**: 화면만 보여 주고 "이 화면으로 무엇을 할 수 있을 것 같나요?"
2. **과제 A: 체크하기**: 장갑을 낀 상태로 현재 단계를 체크하고 다음 단계로 이동 → 몇 번 만에 되는지, 잘못 누른 횟수
3. **과제 B: 값 기록**: 온도 80 °C를 입력 → 입력칸을 쉽게 찾는지, 키보드를 쓰는지 음성/손글씨를 원하는지
4. **과제 C: 실수 되돌리기**: 일부러 다른 단계를 눌러 보게 한 뒤 되돌리기를 찾게 한다
5. **과제 D: 달라진 점**: "계획과 다르게 진행했다"는 상황에서 기록하는 방법을 찾게 한다
6. **마무리 질문 (3분)**: 지금 종이 노트보다 나은가? 가장 걸리는 점은? 빠져 있는 것은?

## 관찰 기록

| 항목 | 기준 | 기록 |
|---|---|---|
| 체크까지 걸린 탭 수 | 1회 | |
| 잘못 누른 횟수 | 0~1회 | |
| 입력칸 찾는 시간 | 3초 이내 | |
| 되돌리기 찾음 | 도움 없이 | |
| 달라진 점 버튼 찾음 | 도움 없이 | |
| 글자가 작다는 반응 | 없음 | |
| 화면이 가려지거나 반사됨 | 없음 | |

## 결과 반영

- 체크 영역이 작다는 반응이 있으면 `--check-size`, `--touch-min`을 키운다. (`tokens.css`)
- 기기를 쓰기 어렵다는 반응이 많으면 "사후 입력 모드"(수행 후 한 번에 체크)를 Phase 3 범위에 넣는다.
- 달라진 점 버튼을 못 찾으면 위치와 이름을 바꾼다. 아직 s3이지만 버튼 자리는 확정해 둔다.

## 통과 기준

- 참여자 1명 이상이 "쓸 만하다"고 말한다.
- 체크와 값 입력 과제는 도움 없이 모두 완료한다.
- 치명적인 오해(예: 체크를 완료 처리로 착각해 기록이 사라질까 걱정)는 문구나 동작으로 해결한다.
