# Spec: 구조 재구성 (클린 아키텍처, feature-first)

- **상태**: 확정 대기(사용자 확인 필요)
- **날짜**: 2026-10-20
- **작업 의도**: `docs/Intent.md`의 "v2 구조 재구성"
- **관련 문서**: `문제정의.md`, PRD §4 KR3~KR5, IA(Component Reuse Map), ERD(변경 없음), ADR 0002·0003
- **짝 문서**: [plan.md](./plan.md)

## 1. 해결하려는 문제

- **지금 상태**: 코드가 계층형 폴더(`pages/components/services/hooks`)에 모여 있고 300줄이 넘는 파일이 9개다. 화면과 저장소 구현이 가까이 있어 한 곳을 고치면 어디가 깨지는지 알기 어렵다. 저장소 구현은 local·remote 두 벌이고, 서버 저장소의 동시 수정 충돌은 시험으로 고정되어 있지 않다(QA 13번 Fail).
- **근거**: 파일 줄 수 측정(`localBackend.ts` 471, `SettingsPage.tsx` 466, `remoteBackend.ts` 431, `AnalysisView.tsx` 384, `insights.ts` 382, `RunPage.tsx` 381, `analysis.ts` 373, `stats.ts` 369, `DataGrid.tsx` 339), QA 체크리스트 13번.
- **막혀서 생기는 일**: 다음 기능(팀 공유, 첨부 등)을 얹을 때 변경 범위를 예측하기 어렵고, 규칙이 문서에만 있어 지켜지지 않는다.
- **PRD 연결**: KR3(300줄·경계 0건), KR4(기존 시험 불변), KR5(문서 일치).

## 3. 핵심 기능과 요구사항

| 번호 | 요구사항 | 우선순위 | 화면·주소 (IA) | 데이터 (ERD) |
|---|---|---|---|---|
| FR-1 | 개발자는 어떤 `src` 파일도 300줄(빈 줄·주석 제외)을 넘지 않는다는 것을 린터로 확인할 수 있다 | Must | — | — |
| FR-2 | `domain`은 React·저장소·`data`를 import하지 않고, `features/*`는 `data`의 구현을 직접 import하지 않으며, 린터가 위반을 오류로 알린다 | Must | — | — |
| FR-3 | 300줄을 넘는 파일 9개가 책임별로 나뉜다(공개 동작 불변) | Must | — | — |
| FR-4 | 코드가 `src/domain`, `src/data`, `src/features/*`, `src/shared` 구조로 옮겨진다 | Must | 모든 화면 | — |
| FR-5 | local·remote 저장소가 하나의 `Repository` 계약과 공용 계약 시험으로 검증된다 | Must | — | 7표 |
| FR-6 | 서버 저장소 계약 시험에 "A가 먼저 저장하면 B의 저장은 `ConflictError`" 시나리오가 있다 | Must | `/experiments/:id` 등 편집 화면 | `version` |
| FR-7 | 화면과 기능은 lablog v1과 같게 동작한다(기존 시험 450개·E2E 112개 불변) | Must | 전체 | 전체 |
| FR-8 | IA의 주소 목록과 앱의 라우트 목록이 일치하는지 시험이 확인한다 | Should | IA | — |
| FR-9 | lablog 백업 JSON을 v2에 가져오면 건수가 모두 맞는다 | Should | 설정 → 백업·이전 | 7표 |

**오류와 예외**

| 번호 | 상황 | 사용자에게 보이는 것 |
|---|---|---|
| ER-1 | 이동 중 import 경로가 깨짐 | 개발 중 타입·빌드 오류로 즉시 드러난다(사용자에게 보이지 않아야 함) |
| ER-2 | 충돌(두 탭 저장) | "다른 탭에서 이 항목을 먼저 수정했습니다"와 "내 내용으로 덮어쓰기"(v1과 같음) |

## 4. 성공 기준

| 번호 | 확인 방법 (할 일 → 기대하는 결과) | 대응 |
|---|---|---|
| SC-1 | `npm run lint` → `max-lines` 위반 0건, 모든 `src` 파일 ≤ 300줄 | FR-1, FR-3 |
| SC-2 | `npm run lint` → import 경계 위반 0건. 일부러 `domain`에서 `react`를 import하면 오류가 난다(규칙이 실제로 걸린다) | FR-2 |
| SC-3 | `npm run check` → 기존 450개 시험 통과(시험 파일 수정 없이, import 경로 변경 제외) | FR-7 |
| SC-4 | `npx playwright test` → E2E 112개 통과, 13개 skip 그대로 | FR-7 |
| SC-5 | 폴더 목록이 `domain / data / features / shared / app` 구조이고 `pages`·`components`·`services`·`hooks` 최상위 폴더가 없다 | FR-4 |
| SC-6 | 공용 계약 시험(`runBackendContract`)이 local·remote(메모리)에 같은 시나리오를 돌려 통과하고, 충돌 시나리오가 포함된다 | FR-5, FR-6 |
| SC-7 | 화면 목록(IA)과 라우트 목록 비교 시험이 통과한다 | FR-8 |
| SC-8 | 백업 JSON 가져오기 후 "건수 비교 표"의 서버에 없는 행이 모두 0이다 | FR-9 |
| SC-9 | 눈으로 확인: 홈·실험·수행 모드·데이터 허브가 v1과 같게 보인다(스크린샷 비교 또는 QA 시트) | FR-7 |

- **지켜야 할 선**: 사용자에게 보이는 동작·문구·화면이 바뀌지 않는다. 데이터 형식·표 구조가 바뀌지 않는다.
- 이 표가 직접 QA 시트의 시나리오가 된다.

## 5. 제외 범위

- 새 기능 추가, 화면 디자인 변경, 표 구조 변경(마이그레이션 없음).
- 로컬 → 서버 자동 동기화, Realtime 변경 알림, 팀 공유.
- 새 라이브러리 도입(린터 규칙은 기존 oxlint로 하고, 불가하면 시험으로 대체한다).
- lablog(`main`)와 `../lab` 폴더의 변경.
