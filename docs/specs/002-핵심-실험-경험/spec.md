# Spec: 핵심 프로젝트·실험 경험

- **상태**: 확정(2026-10-20)
- **날짜**: 2026-10-20
- **작업 의도**: `docs/Intent.md`의 "핵심 실험 경험 재설계"
- **관련 문서**: PRD §4·§6·§7 · IA(새 실험·실험 목록·실험 개요·프로젝트 현황) · UJ Journey 1~4 · ERD(`experiments`, `steps`, `data_items`, `deviations`, `templates`)
- **짝 문서**: [plan.md](./plan.md) (사용자 확인 대기)

> 이 문서는 무엇을, 왜 바꾸는지만 정한다. 구현 방법과 파일은 plan에서 정한다.

## 1. 해결하려는 문제

- **지금 상태**: 새 실험 화면에 목적·프로젝트·태그·템플릿·마지막 실험 이어받기가 한꺼번에 있다. 실험 목록은 제목·상태·진행률 중심이라 주요 조건·결과를 보려면 상세 화면을 열어야 한다.
- **근거**: 사용자 의견(“실험 기록이 한눈에 잘 보이고, 실험 등록이 빠를 뿐 아니라 편리해야 한다”)과 현재 화면·코드 확인. 프로젝트 자동 선택과 마지막 실험 이어받기 기반은 이미 있다.
- **막혀서 생기는 일**: 반복 실험을 등록할 때 사용자가 같은 내용을 다시 판단·입력하고, 기록 후에도 여러 화면을 열거나 엑셀로 다시 정리하게 된다.
- **PRD 목표와의 연결**: KR1(편리한 최초 저장), KR2(반복 입력 제거), KR3(목록에서 파악), KR4(누락 감소), KR5(데이터·품질 보존).

## 2. 주요 사용자

| 사용자 | 장면 | 기기 |
|---|---|---|
| 개인 연구원 | 프로젝트 안에서 반복 실험을 등록하고 수행하기 직전 | PC / 태블릿 |
| 개인 연구원 | 실험 종료 후 최근 기록과 결과를 비교할 때 | PC / 태블릿 |
| 개인 연구원 | 프로젝트의 진행·누락·다음 실험을 검토할 때 | PC |

- UJ Journey 1~4에 해당한다.
- 로그인 사용자는 본인 데이터만 보고 수정한다. 로컬 저장소 모드도 유지한다.

## 3. 핵심 기능과 요구사항

| 번호 | 요구사항 | 우선순위 | 화면·주소 | 데이터 |
|---|---|---|---|---|
| FR-1 | 사용자는 홈·프로젝트·실험·데이터의 네 가지 주 메뉴로 핵심 작업에 접근할 수 있다 | Must | 앱 전체 | — |
| FR-2 | 프로젝트에서 새 실험을 시작하면 프로젝트가 자동 선택되고 제목이 제안되며, 제목만으로 준비 상태를 저장할 수 있다 | Must | `/experiments/new` | `projects`, `experiments` |
| FR-3 | 사용자는 빈 실험, 같은 프로젝트의 마지막 실험, 직접 고른 기존 실험 중 하나에서 시작할 수 있다 | Must | `/experiments/new` | `experiments` |
| FR-4 | 사용자는 이어받을 절차·조건·결과 항목을 만들기 전에 확인할 수 있고, 결과 값·단계 체크·메모는 새 실험에 복사되지 않아야 한다 | Must | `/experiments/new` | `steps`, `data_items` |
| FR-5 | 사용자는 이어받은 실험에서 달라진 목적·절차·조건만 수정하고 준비 저장·절차 입력·바로 수행 중 다음 행동을 고를 수 있다 | Must | `/experiments/new` | `experiments`, `steps`, `data_items` |
| FR-6 | 실험 목록은 제목·프로젝트·상태·진행률·주요 조건 최대 3개·주요 결과 최대 3개·편차 유무·수정 시각을 한 행에 보여 줘야 한다 | Must | `/experiments` | `experiments`, `steps`, `data_items`, `deviations` |
| FR-7 | 사용자는 실험 목록에서 제목·목적 키워드와 프로젝트·상태·기간으로 찾고 정렬·페이지 이동할 수 있다 | Must | `/experiments?q=…` | `experiments` |
| FR-8 | 실험 개요 첫 화면은 목적·상태·진행률·주요 조건·결과·편차·누락과 다음 행동을 먼저 보여 줘야 한다 | Must | `/experiments/:id` | `experiments`, `steps`, `data_items`, `deviations` |
| FR-9 | 프로젝트 현황은 새 실험 진입점, 진행 중 실험, 최근 완료 실험의 주요 조건·결과, 빠진 기록을 먼저 보여 줘야 한다 | Must | `/projects/:id` | `projects`, `experiments`, `steps`, `data_items`, `deviations` |
| FR-10 | 별도 검색·템플릿 화면과 새 템플릿 생성 진입점은 제거하되 기존 템플릿 데이터와 백업 호환은 유지해야 한다 | Must | `/search`, `/templates` 제거 | `templates` 보존 |
| FR-11 | 입력은 자동 저장되고 저장 중·저장됨·실패·충돌 상태를 보여 주며, 실패 후 입력을 잃지 않고 다시 시도할 수 있어야 한다 | Must | 모든 편집 화면 | 전체 기록 |
| FR-12 | 결론과 다음 행동을 실험 개요에 명시적으로 기록할 수 있다 | Should(후속) | `/experiments/:id` | 후속 마이그레이션 검토 |

**오류와 예외**

| 번호 | 상황 | 사용자에게 보이는 것 |
|---|---|---|
| ER-1 | 이어받을 원본 실험이 삭제됨 | 원본을 사용할 수 없다는 안내와 다른 실험/빈 실험 선택 |
| ER-2 | 이전 결과 값·체크·메모가 복사됨 | 생성을 완료하지 않고 초기화 항목을 알림 |
| ER-3 | 저장 실패 또는 네트워크 끊김 | 입력 유지, 저장 실패/대기 표시와 다시 시도 |
| ER-4 | 다른 탭에서 먼저 수정함 | 충돌 안내와 내 내용으로 덮어쓰기 선택 |
| ER-5 | 검색·필터 결과 없음 | 필터 초기화와 새 실험 만들기 |
| ER-6 | 주요 조건·결과가 3개보다 많음 | 앞쪽 3개와 `외 n개` 표시, 상세 화면으로 이동 |
| ER-7 | 기존 `/search`·`/templates` 주소로 접근 | 실험 목록으로 이동하고 변경된 위치 안내 |

## 4. 성공 기준

| 번호 | 확인 방법 | 대응 요구사항 |
|---|---|---|
| SC-1 | 프로젝트에서 새 실험을 열면 프로젝트가 선택돼 있고 제목만 입력해 준비 상태로 저장된다 | FR-2 |
| SC-2 | 빈 실험·마지막 실험·기존 실험을 각각 선택할 수 있고 생성 전 포함 항목이 보인다 | FR-3, FR-4 |
| SC-3 | 이어받은 실험은 절차·조건·결과 항목을 가지지만 결과 값·단계 체크·메모는 비어 있다 | FR-4 |
| SC-4 | 이어받기 후 달라진 조건 하나만 수정해 준비 저장·절차·수행 중 원하는 화면으로 이동한다 | FR-5 |
| SC-5 | 최근 실험 10건을 목록에서 보고 상태·진행·주요 조건·결과·수정 시각을 10초 안에 구분한다(직접 QA) | FR-6 |
| SC-6 | 실험 목록에서 제목·목적 키워드와 기존 필터를 조합해 원하는 실험을 찾고 주소를 다시 열어도 조건이 유지된다 | FR-7 |
| SC-7 | 실험 개요를 열면 스크롤 전 영역에서 목적·진행·주요 조건·결과·편차·누락과 다음 행동이 보인다(1440×900 기준) | FR-8 |
| SC-8 | 프로젝트 현황에서 진행 중·최근 완료·빠진 기록을 확인하고 두 번 이내 동작으로 후속 실험 등록을 시작한다 | FR-9 |
| SC-9 | 주 메뉴와 라우트에 검색·템플릿이 없고 기존 주소는 실험 목록으로 안내된다. 백업 내보내기·가져오기에서 기존 템플릿 건수는 유지된다 | FR-1, FR-10 |
| SC-10 | 저장 실패·충돌을 재현하면 입력이 남고 다시 시도 또는 덮어쓰기가 가능하다 | FR-11 |
| SC-11 | 결론·다음 행동을 저장하고 새로고침한 뒤 같은 내용이 보인다 | FR-12 |
| SC-12 | 변경된 사용자 여정 시험과 전체 자동 검사가 통과하고, 기존 실험·프로젝트·조건·결과 건수가 유지된다 | FR-1~FR-11 |

- **지켜야 할 선**: 같은 내용을 두 번 입력하지 않는다. 입력을 잃지 않는다. 이전 결과 값을 새 실험에 남기지 않는다. 기존 데이터와 백업을 삭제하지 않는다.

## 5. 제외 범위

- 전역 본문 검색과 철자·유사어 추천은 제거하며 이번 범위에서 다시 만들지 않는다.
- 새 템플릿 생성·편집·적용 UI는 제거한다. 기존 데이터 삭제와 `templates` 표 삭제는 하지 않는다.
- 고급 통계, 데이터 허브, 고객 요구 판정은 유지하지만 이번에 확장하지 않는다.
- 팀 공유, 첨부, 장비 연동, 오프라인 자동 동기화는 다음 버전이다.
- 디자인 전체 교체는 하지 않는다. 엔틱 노트 톤과 기존 접근성·반응형 기준을 유지한다.

## 6. 확정 사항

| 번호 | 결정 | 적용 내용 | 대응 요구사항 |
|---|---|---|---|
| D-1 | 결론·다음 행동 필드는 1차 구현에서 제외 | 기존 데이터로 요약과 다음 작업 진입점만 제공하며 표 구조를 바꾸지 않는다. FR-12와 SC-11은 후속 범위다 | FR-8 |
| D-2 | 주요 조건·결과는 입력 순서 앞쪽 최대 3개 | 나머지는 `외 n개`로 표시하고 상세 화면에서 확인한다 | FR-6, SC-5 |
| D-3 | 등록 30초·최근 10건 파악 10초를 초기 목표로 사용 | 직접 QA에서 측정하고 결과를 기록한다 | SC-1, SC-5 |
| D-4 | 기존 검색·템플릿 주소는 실험 목록으로 이동 | `/experiments`로 이동하고 변경된 위치를 한 번 안내한다 | FR-10, SC-9 |
