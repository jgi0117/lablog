# Plan: 핵심 프로젝트·실험 경험

- **상태**: 구현·자동 QA 완료(2026-10-21, 직접 사용성 QA 대기)
- **날짜**: 2026-10-20
- **짝 문서**: [spec.md](./spec.md) (FR-1~11, SC-1~10·12)
- **작업 의도**: `docs/Intent.md`의 "핵심 실험 경험 재설계"

> 결론·다음 행동 전용 필드(FR-12, SC-11)는 이번 구현에서 제외한다. 새 라이브러리와 DB 마이그레이션 없이 기존 저장소 계약을 사용한다.

## 1. 구현 원칙

- 사용자의 첫 선택은 프로젝트와 시작 방식이다. 목적·태그 같은 부가 정보는 필요할 때 펼친다.
- 이어받기는 생성 전에 절차·조건·결과 항목의 개수와 앞쪽 항목을 미리 보여 준다.
- 이전 결과 값, 단계 완료 상태, 단계 메모는 어떤 시작 방식에서도 복사하지 않는다.
- 전용 검색·템플릿 UI만 제거한다. 저장소의 검색 계약, 템플릿 데이터, 백업·이전 호환 시험은 유지한다.
- 사용자 행동이 바뀌는 기존 시험은 새 spec의 동등하거나 더 강한 검증으로 교체한다. 데이터 보존 시험은 삭제하지 않는다.
- 구현 단위마다 `npm run check`, 화면 흐름 완료 뒤 전체 Playwright를 실행한다.

## 3. 단계별 접근

| 단계 | 목표 | 주요 변경 | 완료 조건 | 되돌리기 |
|---|---|---|---|---|
| 1 | 실험 등록을 편리하게 재구성 | 시험을 먼저 추가한 뒤 시작 방식 선택, 기존 실험 선택, 복사 미리보기, 부가 입력 접기, 준비 저장·절차·바로 수행 이동 구현 | SC-1~4 통과. 결과 값·체크·메모 미복사 회귀 시험 통과 | 등록 화면·서비스 단위 되돌림 |
| 2 | 실험 기록을 목록·개요에서 한눈에 표시 | 목록 키워드/URL 필터와 요약 행, 개요 첫 영역 재배치 | SC-5~7 통과. 500건 목록 성능 2초 기준 유지 | 목록과 개요를 각각 되돌림 |
| 3 | 프로젝트 현황과 핵심 내비게이션 정리 | 프로젝트 현황 우선순위 조정, 4개 메뉴, 전용 검색·템플릿 진입 제거, 구주소 안내 이동 | SC-8~9 통과. 템플릿 데이터·백업 건수 유지 | 현황과 내비게이션을 각각 되돌림 |
| 4 | 저장·충돌 회귀와 사용자 환경 검증 | 저장 실패·충돌 시험, 접근성·키보드·태블릿·성능 E2E 보강 | SC-10·12와 변경 여정 E2E 통과 | 해당 회귀 보강 단위 되돌림 |
| 5 | 전체 회귀·문서·구조 계획 정리 | 전체 자동 검사, 직접 QA, QA·Intent·HANDOFF와 001 후속 계획 갱신 | `npm run check`, 전체 E2E, QA 결과 기록 | 문서 커밋 되돌림 |

각 단계에서 새 계약 시험을 먼저 실패시키고 같은 단계 안에서 구현해 통과시킨다. 실패한 시험 상태는 커밋·push하지 않는다. 완료 단계는 기능 단위 커밋으로 나누고 `v2`에 push한다. 001의 구조 이동은 002 완료 뒤 삭제된 검색·템플릿 코드를 제외해 다시 계획한다.

## 4. 시험 변경 원칙

### 유지할 시험

- `data/local/migration.test.ts`, `services/migrate.test.ts`, `phase8.test.tsx`의 백업 파싱: 템플릿 데이터 보존.
- backend 검색 계약과 `services/search.test.ts`: 저장소 호환과 기존 데이터 안전망.
- Journey 1 수행, 요구사항, 데이터 허브, 접근성, 키보드, 태블릿, 성능 시험.

### 교체·추가할 시험

| 성공 기준 | 자동 검증 |
|---|---|
| SC-1~4 | 프로젝트 자동 선택·제안 제목·세 가지 시작 방식·미리보기·선택적 이어받기·다음 이동을 React 통합 시험과 E2E로 검증 |
| SC-5~7 | 검색어와 필터의 URL 유지, 최대 3개+`외 n개`, 개요 첫 영역의 주요 정보 표시를 검증 |
| SC-8 | 프로젝트 현황에서 두 동작 이내 후속 실험 시작과 진행/완료/누락 구분을 검증 |
| SC-9 | 4개 메뉴, 구주소 이동 안내, 템플릿 백업 건수 보존을 검증 |
| SC-10 | 기존 debounced save·외부 변경 시험을 유지하고 입력 보존/재시도를 화면 시험으로 보강 |
| SC-12 | 전체 Vitest·Playwright·접근성·태블릿·성능 회귀 |

`j2-search.spec.ts`는 전용 검색 여정을 실험 목록의 제목·목적 검색과 필터 여정으로 바꾼다. `j3-reuse.spec.ts`는 템플릿 생성 여정을 선택한 기존 실험 이어받기 여정으로 바꾸고, 별도의 백업 시험은 템플릿 보존 검증으로 남긴다. 이는 시험 약화가 아니라 제거된 UI 계약을 새 핵심 계약으로 교체하는 것이다.

## 5. 실행 명령과 기준

```bash
npm --prefix app run check
cd app && npx playwright test
```

- 시작 기준선: Vitest 450 통과·2 skip, Playwright 112 통과·13 skip.
- 변경 후 개수는 UI 계약 교체로 달라질 수 있으므로 개수보다 기존 비대상 시나리오 전부 통과와 새 SC 커버리지를 기록한다.
- 직접 QA: 1440×900에서 최근 실험 10건 파악 10초, 프로젝트에서 준비 실험 저장 30초, 키보드와 태블릿 흐름.
- Supabase 통합·RLS 시험은 시험 계정이 없으면 `No Run`으로 기록하고 운영 데이터에는 쓰지 않는다.

## 6. 위험과 방어선

| 위험 | 방어 |
|---|---|
| 목록 요약을 실험별로 읽어 느려짐 | 기존 bundle 로더를 재사용·보완하고 500건 성능 E2E를 유지한다 |
| 결과 값이나 수행 상태가 복사됨 | 복제 서비스 시험을 먼저 추가하고 생성 직후 빈 값·미완료·빈 메모를 단언한다 |
| 템플릿 UI 삭제 중 데이터까지 제거 | backend·타입·백업 코드는 건드리지 않고 round-trip 시험을 유지한다 |
| 검색 화면 제거로 찾기 기능 퇴행 | 제목·목적 검색을 목록 URL 필터에 넣고 기존 필터·정렬·페이지 이동과 조합 시험한다 |
| 한 화면 정보 과밀 | 목록은 각 3개로 제한하고 전체 값은 개요 링크로 넘긴다 |
| 001과 동시에 대규모 이동해 회귀 원인 불명 | 002 기능을 현재 구조에서 먼저 끝내고 001은 그 뒤 재계획한다 |

## 8. 진행 기록

- 1~3단계 구현 완료: 세 가지 시작 방식·복사 미리보기·부가 입력 접기·목록 검색/요약·개요/프로젝트 요약·4개 내비게이션·구주소 안내 이동.
- 기존 템플릿 데이터와 검색 저장소 계약은 유지하고 전용 UI만 제거했다.
- `npm run check`: 통과, Vitest 448 pass / 2 skip(총 450).
- Chromium 핵심 여정·요구·키보드·성능 통과. 500건/4,000단계에서 목록 415ms, 최초 검색 380ms.
- 접근성 표시명 불일치를 수정했고 Chromium 전체 화면·대화상자 axe 검사를 통과했다.
- 브라우저별 전체 회귀 합계는 기준선과 같은 112 pass / 13 skip이다. Firefox는 Codex 샌드박스에서 브라우저가 crash해 샌드박스 밖에서 검증했다.
- 직접 30초 등록·10초 파악·실기기 태블릿 QA는 사용자 확인이 필요하다. 상세는 `docs/qa/QA-002-핵심-실험-경험.md`.
