## User Journeys: 프로젝트·실험 로그

**풀려는 문제**: 실험 등록의 반복 부담을 줄이고, 기록과 프로젝트 진행을 한눈에 파악한다.

감정과 시간 기준은 `[가정]`이며 직접 QA와 실험대 관찰로 보정한다.

---

### Journey 1: 편리하게 새 실험 등록

**Overview**
- 우선순위: Critical
- 사용자: 여러 프로젝트와 반복 실험을 병행하는 연구원
- 빈도: 매일
- 성공 지표: 30초 안에 최초 저장, 반복 입력한 항목 수, 등록 중 이탈률

**목표**
> “앱이 프로젝트와 이전 실험을 기억해서, 달라진 것만 입력하고 바로 실험을 시작하고 싶다.”

**전제**
- 로그인한 상태
- 프로젝트 화면 또는 전역 `+ 새 실험`에서 시작

**Step 1. 최소 정보로 시작**
- 사용자 행동: 프로젝트와 제목을 확인한다. 프로젝트에서 들어오면 제목만 확인한다.
- 시스템 반응: 프로젝트 자동 선택, 다음 번호를 포함한 제목 제안. 제목만으로 저장 가능.
- 성공 기준: 필수 입력은 제목 하나. 프로젝트 밖에서 시작하면 프로젝트 선택을 포함해 두 개 이하.
- 마찰: 무엇을 써야 할지 모름 → 기존 프로젝트·최근 제목을 근거로 제안.

**Step 2. 시작 방법 선택**
- 사용자 행동: 빈 실험 / 마지막 실험 / 기존 실험 중 하나를 고른다.
- 시스템 반응: 이어받을 절차·조건·결과 항목과 제외할 결과 값·체크·메모를 미리 보여 준다.
- 성공 기준: 복사 결과를 만들기 전에 이해할 수 있다.
- 마찰: 잘못된 실험 선택 → 원본 바꾸기와 빈 실험으로 돌아가기 제공.

**Step 3. 달라진 부분만 수정**
- 사용자 행동: 이번 실험에서 바뀐 목적·조건값·절차만 수정한다.
- 시스템 반응: 프로젝트에서 사용한 조건명·단위를 제안하고 즉시 저장 상태를 보여 준다.
- 성공 기준: 같은 절차·조건·결과 항목을 다시 타이핑하지 않는다.

**Step 4. 다음 행동 선택**
- 사용자 행동: 준비 상태로 저장, 절차 입력, 바로 수행 중 하나를 고른다.
- 시스템 반응: 선택한 화면으로 이동하며 생성된 실험의 요약을 보여 준다.
- 성공 기준: 사용자가 다음에 할 일을 찾지 않아도 된다.

**오류 시나리오**
- **E1 중단**: 생성 전 입력은 임시 보존하거나 이탈 경고, 생성 후 입력은 자동 저장.
- **E2 복제 오류**: 결과 값·단계 체크·메모가 복사되면 생성 취소 또는 되돌리기.
- **E3 저장 실패**: 입력을 유지하고 다시 시도. 서버 연결 상태 표시.
- **E4 동시 수정**: 다른 탭의 변경을 알리고 덮어쓰기 여부를 묻는다.

### Journey 2: 실험 기록을 한눈에 파악

**Overview**
- 우선순위: Critical
- 빈도: 매일
- 성공 지표: 최근 10건 파악 시간, 상세 화면을 열지 않고 대상을 고른 비율

**목표**
> “실험을 하나씩 열지 않고도 왜 했고 어디까지 했으며 무엇이 나왔는지 알고 싶다.”

**Step 1. 목록 훑기**
- 사용자 행동: 홈·프로젝트·실험 목록을 본다.
- 시스템 반응: 제목, 프로젝트, 목적, 상태, 진행률, 주요 조건·결과, 편차, 수정 시각을 같은 순서로 표시한다.
- 성공 기준: 최근 10건을 10초 안에 구분한다 `[가정]`.

**Step 2. 필요한 실험만 열기**
- 사용자 행동: 관심 있는 실험 행을 연다.
- 시스템 반응: 개요 상단에 목적·진행·조건·결과·편차·누락과 다음 행동을 요약한다.
- 성공 기준: “왜/어디까지/무엇이 나왔나”를 첫 화면에서 확인한다.

**Step 3. 목록에서 찾기**
- 사용자 행동: 제목·목적 키워드, 프로젝트·상태·기간 필터를 사용한다.
- 시스템 반응: 조건에 맞는 실험만 남기고 필터를 주소에 보존한다.
- 성공 기준: 별도 검색 화면으로 이동하지 않는다.

**오류 시나리오**
- **E1 결과 없음**: 필터 초기화와 새 실험 만들기 제공.
- **E2 값이 너무 많음**: 목록에는 주요 항목만 표시하고 나머지는 `외 n개`로 접는다.
- **E3 단위 불일치**: 값 옆에 단위 확인 표시, 상세 수정으로 이동.

### Journey 3: 이전 실험을 이어서 반복

**Overview**
- 우선순위: Critical
- 빈도: 주 여러 번
- 성공 지표: 이어받기로 만든 실험 비율, 다시 입력한 항목 수, 잘못 복사된 결과 0건

**목표**
> “지난 실험과 같은 부분은 그대로 쓰고 바꾼 조건만 수정하고 싶다.”

**Step 1. 원본 선택**: 프로젝트의 마지막 실험 또는 기존 실험을 고른다.

**Step 2. 이어받기 확인**: 절차·조건·결과 항목을 선택한다. 결과 값·단계 체크·메모는 항상 제외된다.

**Step 3. 차이 입력**: 바뀐 조건과 절차를 수정하고 수행을 시작한다.

**Step 4. 편차 기록**: 계획과 실제가 달라지면 해당 단계에서 편차와 이유를 남긴다.

**오류 시나리오**
- **E1 원본이 삭제됨**: 사용할 수 없음을 알리고 다른 실험 또는 빈 실험을 선택한다.
- **E2 이전 결과가 남음**: 생성 검증에서 차단하고 사용자에게 초기화 사실을 알린다.

---

### Journey 4: 프로젝트 진행과 최근 결과 검토

**Overview**
- 우선순위: Critical
- 빈도: 주 1~2회, 실험 종료 후
- 성공 지표: 빠진 기록의 주별 감소, 프로젝트에서 후속 실험까지 걸린 시간

**목표**
> “프로젝트에서 무엇을 했고 무엇이 나왔으며 다음 실험은 무엇인지 한곳에서 보고 싶다.”

**Step 1. 진행 중 실험 확인**: 상태·진행률·남은 단계와 바로 이어하기를 본다.

**Step 2. 최근 결과 비교**: 최근 완료 실험의 주요 조건·결과·편차를 행으로 비교한다.

**Step 3. 빠진 기록 수정**: 빈 결과·미완료 단계·단위 불일치에서 해당 실험으로 이동해 고친다.

**Step 4. 후속 실험 시작**: 프로젝트 맥락과 마지막 실험을 이어받아 새 실험을 만든다.

**오류 시나리오**
- **E1 의도적으로 비운 항목**: 현재는 계속 표시한다. “확인함” 처리는 파일럿 후 결정.
- **E2 비교할 숫자가 부족함**: 표는 보여 주되 분석할 수 없는 이유를 설명한다.

---

### Journey 5: 수행하며 바로 기록

**Overview**
- 우선순위: Critical
- 빈도: 매일
- 성공 지표: 단계 누락, 재입력 횟수, 저장 실패 후 복구율

**목표**
> “실험 단계를 놓치지 않고 진행하면서 그 자리에서 기록하고 싶다.”

**Step 1. 현재 단계 수행**: 큰 체크 영역, 메모·수치 입력, 즉시 저장 표시.

**Step 2. 계획과 달라짐 기록**: 현재 단계에서 편차와 이유를 남긴다.

**Step 3. 완료**: 미완료 단계·빈 결과를 확인하고 완료하거나 돌아가서 채운다.

**오류 시나리오**
- 네트워크 끊김, 실수 체크, 단계 건너뜀, 충돌 모두 입력을 잃지 않는 복구 경로를 제공한다.

---

### Journey 6: 데이터 확인과 내보내기

**Overview**
- 우선순위: High
- 빈도: 주 1회
- 성공 지표: 별도 엑셀 재정리 횟수, 내보내기 성공률

**목표**
> “프로젝트의 조건·결과를 한 표에서 비교하고 필요할 때 파일로 내보내고 싶다.”

1. 프로젝트 데이터에서 실험 × 항목 표를 본다.
2. 이상치·빈 값·단위 불일치를 확인하고 해당 실험으로 이동한다.
3. CSV 또는 백업 JSON을 내려받는다.
4. 고급 통계는 필요할 때 데이터 화면에서 연다.

---

### Journey 7: 로그인·백업·이전

- 우선순위: High
- 목표: 어느 기기에서든 내 기록을 안전하게 이어서 사용한다.
- 로그인은 운영자가 만든 개인 계정으로 하며 가입은 닫는다.
- 기존 백업은 템플릿 데이터를 포함해 그대로 가져오고 내보낸다.
- 로컬 데이터를 서버로 옮겨도 원본을 자동 삭제하지 않는다.

---

### 검증 계획

- 프로젝트 안에서 새 실험을 만들어 최초 저장까지 시간을 잰다.
- 반복 실험에서 다시 입력한 항목과 잘못 복사된 결과가 있는지 확인한다.
- 최근 실험 10건을 보고 목적·상태·주요 결과를 말하게 한다.
- 실험대에서 PC·태블릿 입력과 44px 터치 영역이 실제로 충분한지 관찰한다.
- 별도 검색·템플릿 화면 없이 필요한 실험과 반복 시작을 완료할 수 있는지 확인한다.
