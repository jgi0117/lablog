## Information Architecture: 프로젝트·실험 로그

**풀려는 문제**: 실험을 편리하게 등록하고, 프로젝트와 실험의 핵심 기록을 한눈에 파악하기 어렵다.

**구성 기준**: 등록 → 수행·기록 → 한눈에 확인 → 프로젝트 검토 → 필요할 때 분석.

이 문서는 spec 002의 목표 구조다. 현재 앱에는 `/search`, `/templates`와 전역 검색이 남아 있어 구현 전까지 코드와 의도적으로 다르다.

---

### Site Map

- 홈 `/`
  - 오늘 진행할 실험
  - 기록이 빠진 실험
  - 최근 수정한 실험
- 프로젝트 `/projects`
  - 프로젝트 상세 `/projects/:id`
    - 현황 `/projects/:id`
    - 고객 요구 `/projects/:id/requirements`
    - 데이터 `/projects/:id/data`
    - 분석 `/projects/:id/analysis`
    - 새 실험 `/experiments/new?project=:id`
- 실험 `/experiments`
  - 목록 안 검색·필터 `?q=&project=&status=&period=&sort=&page=`
  - 새 실험 `/experiments/new`
  - 실험 상세 `/experiments/:id`
    - 개요 `/experiments/:id`
    - 절차 `/experiments/:id/steps`
    - 수행 모드 `/experiments/:id/run`
    - 조건·결과 `/experiments/:id/data`
    - 편차 `/experiments/:id/deviations`
- 데이터 `/data`
  - 전체 표 `/data`
  - 분석 `/data/analysis`
  - 내보내기 `/data/export`
- 휴지통 `/trash`
- 로그인(서버 저장소일 때 앱 셸 밖)
- 이전 `/migrate`
- 설정 `/settings`

제거 대상:
- 별도 검색 `/search`: 실험 목록의 검색·필터로 합친다.
- 템플릿 `/templates`: 화면과 생성 진입점을 제거한다. 기존 데이터와 백업은 보존한다.

---

### Navigation Model

- **Primary navigation**: 홈 · 프로젝트 · 실험 · 데이터(4개).
- **Secondary navigation**: 프로젝트 상세는 현황/고객 요구/데이터/분석, 실험 상세는 개요/절차/조건·결과/편차.
- **Utility navigation**: `+ 새 실험`, 설정. 전역 검색창은 제거한다.
- **Mobile navigation**: 홈·프로젝트·실험·데이터 하단 탭. 새 실험은 항상 보이는 주요 동작으로 둔다.
- **Navigation depth**: 최대 2단계. 수행 모드는 앱 셸 없는 전체 화면이다.

---

### Content Hierarchy

#### 홈

1. **진행 중 실험** — 지금 이어서 할 일과 남은 단계 수
2. **기록이 빠진 실험** — 빈 결과·미완료 단계·단위 불일치
3. **최근 실험** — 목적·상태·주요 결과·수정 시각
4. 프로젝트 요약과 데이터 바로가기

#### 프로젝트 현황

1. **새 실험** — 프로젝트가 자동 선택된 등록 화면으로 이동
2. **진행 중 실험** — 상태·진행률·다음 단계
3. **최근 완료 실험** — 주요 조건·결과와 편차를 행 단위로 비교
4. **빠진 기록** — 해당 실험으로 바로 이동
5. 고객 요구 달성, 타임라인, 데이터·분석

#### 실험 목록

1. **키워드와 필터** — 제목·목적 키워드, 프로젝트·상태·기간
2. **밀도 높은 실험 행** — 제목, 프로젝트, 상태, 진행률, 주요 조건·결과, 편차 유무, 수정 시각
3. 정렬과 페이지 이동
4. 빈 상태와 필터 초기화

#### 새 실험

1. **프로젝트와 제목** — 프로젝트 안에서 들어오면 자동 선택, 제목 제안
2. **시작 방법** — 빈 실험 / 마지막 실험 이어받기 / 기존 실험 선택
3. **이어받을 내용 확인** — 절차·조건·결과 항목을 선택. 결과 값·단계 체크·메모는 제외
4. **달라진 부분** — 목적·태그·조건값을 필요할 때만 수정
5. **다음 행동** — 준비 상태로 저장 / 만들고 절차 입력 / 바로 수행

처음에는 프로젝트·제목만 보여 주고 나머지는 시작 방법을 선택한 뒤 펼치는 점진적 공개를 쓴다.

#### 실험 개요

1. **한눈에 요약** — 목적, 상태, 진행률, 프로젝트, 수정 시각
2. **주요 조건과 결과** — 이름·값·단위를 간단히 비교
3. **편차와 누락** — 실제 절차와 달라진 점, 빈 결과
4. **다음 행동** — 절차 편집, 수행 이어가기, 결과 입력, 후속 실험 만들기
5. 담당자·태그·날짜와 삭제 같은 보조 정보

#### 수행 모드

1. 현재 단계와 큰 체크 영역
2. 단계 메모·수치 입력
3. 전체 진행률과 이전·다음
4. 편차 기록

#### 데이터

1. 프로젝트 또는 전체 실험 × 항목 표
2. 필터와 CSV 내보내기
3. 관계·추세·이상치 분석

고급 통계는 유지하지만 핵심 등록·기록 화면보다 앞에 두지 않는다.

---

### User Flows

#### 프로젝트에서 새 실험 등록

1. 프로젝트 현황에서 `+ 새 실험`을 누른다.
2. 프로젝트는 이미 선택되고 제목이 제안된다.
3. 빈 실험 또는 이전 실험 이어받기를 고른다.
4. 이어받는 경우 절차·조건·결과 항목을 확인하고 달라진 부분만 수정한다.
5. 준비 상태로 저장하거나 바로 절차·수행 화면으로 이동한다.

#### 기록을 한눈에 확인

1. 홈·프로젝트·실험 목록에서 실험 행을 본다.
2. 상태·진행·주요 조건·결과·편차를 비교한다.
3. 더 볼 필요가 있는 실험만 개요로 연다.
4. 개요에서 누락을 고치거나 후속 실험을 만든다.

#### 지난 실험 찾기

1. 실험 목록의 키워드·프로젝트·상태·기간 필터를 쓴다.
2. 결과 행의 목적·주요 조건·결과를 보고 대상을 고른다.
3. 결과가 없으면 필터 초기화와 새 실험 만들기를 안내한다.

### Naming Conventions

| 개념 | 화면 이름 | 비고 |
|---|---|---|
| 한 번의 시도 | 실험 | 테스트·런 금지 |
| 이전 기록 기반 생성 | 이어받기 | 템플릿 대신 실제 실험을 기준으로 함 |
| 그대로 새 기록 생성 | 복제 | 결과 값·체크·메모는 비움 |
| 계획과 실제의 차이 | 편차 | 달라진 점과 이유 |
| 아직 쓰지 않은 값 | 빈 결과 | `0`과 구분 |

### Component Reuse Map

| 구조 요소 | 쓰이는 곳 | 비고 |
|---|---|---|
| 실험 요약 행 | 홈·프로젝트 현황·실험 목록 | 표시 밀도만 다르고 정보 순서는 같음 |
| 시작 방법 선택 | 새 실험·후속 실험 | 빈 실험/마지막/기존 실험 |
| 이어받기 미리보기 | 새 실험 | 포함·제외 항목과 결과값 초기화를 명시 |
| 단계 체크 | 수행 모드·절차 | 수행에서는 큰 터치 영역 |
| 이름-값-단위 입력 | 조건·결과·수행 | 프로젝트의 기존 이름·단위 자동 완성 |
| 저장·충돌 상태 | 모든 편집 화면 | 저장 중/저장됨/실패/충돌 |

---

### Content Growth Plan

- 실험은 계속 쌓이므로 프로젝트·상태·기간·키워드 필터와 페이지 나눔을 쓴다.
- 목록 검색은 우선 제목·목적을 대상으로 한다. 본문 전체 검색은 실제 필요가 확인되면 다시 검토한다.
- 조건·결과 이름과 단위는 프로젝트 안에서 자동 완성해 열이 갈라지는 문제를 줄인다.
- 기존 템플릿 데이터는 삭제하지 않고 백업 호환을 위해 유지한다.

### URL Strategy

- 패턴: `/섹션/:id/하위화면`.
- 필터·검색·정렬·페이지는 실험 목록의 쿼리 문자열에 둔다.
- 기존 `/search`, `/templates` 북마크는 구현 시 `/experiments`로 안전하게 안내하거나 이동시킨다.
- 모든 주소는 새로고침과 직접 열기를 지원한다.
