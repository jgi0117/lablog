## Information Architecture: 실험 기록 서비스

**풀려는 문제**: 실험 기록이 여러 곳에 흩어져 찾기도 재현하기도 어려운 문제

**구성 기준**: s1 모으기 → s2 찾기 → s3 다시 쓰기

가정: 사용 기기는 PC와 태블릿이다. (확인 필요)

---

### Site Map

- 홈 `/`
  - 실험 목록 `/experiments` (s2)
    - 실험 만들기 `/experiments/new` (s1)
    - 실험 상세 `/experiments/:id`
      - 개요 `/experiments/:id` (s1)
      - 절차 편집 `/experiments/:id/steps` (s1)
      - 수행 모드 `/experiments/:id/run` (s1, 앱 셸 없는 전체 화면)
      - 조건·결과 `/experiments/:id/data` (s1)
      - 첨부 `/experiments/:id/files` (s2, P1)
      - 편차 기록 `/experiments/:id/deviations` (s3, P1)
  - 검색 `/search` (s2)
  - 템플릿 `/templates` (s3, P1)
    - 템플릿 편집 `/templates/:id`
  - 팀 `/team` (s3, P2)
- 설정 `/settings`
  - 프로젝트·태그 `/settings/projects`
  - 프로필 `/settings/profile`

---

### Navigation Model

- **Primary navigation**: 홈 · 실험 · 검색 · 템플릿 (최대 5개). 팀은 P2에 추가.
- **Secondary navigation**: 실험 상세 안의 탭 — 개요 / 절차 / 조건·결과 / 첨부 / 편차. 실험 목록의 필터(프로젝트·태그·상태).
- **Utility navigation**: 전역 검색창, + 새 실험, 설정, 프로필. 모든 화면 상단에 둔다.
- **Mobile navigation**: 하단 탭(홈·실험·검색·템플릿). 수행 모드는 전체 화면. [가정]

---

### Content Hierarchy

**홈 (대시보드)**
1. 진행 중 실험 — 오늘 해야 할 일이라 가장 먼저
2. 미완료 단계 — 놓친 것을 바로 알리기 위해
3. 최근 본 실험 — 다시 열기 쉽게

**실험 목록**
1. 검색창과 필터 — 찾기가 이 화면의 목적
2. 실험 카드: 제목, 상태, 진행률, 담당자
3. 정렬 (최근 수정순 기본)

**수행 모드 (실험 상세 · 절차)**
1. 현재 단계와 체크 — 수행 중 가장 자주 쓰는 동작
2. 단계 메모·수치 입력 — 체크와 같은 화면에서 해결
3. 전체 진행률, 이전·다음 단계
4. 편차 기록 버튼 (접어 둠)

**검색 결과**
1. 일치한 문구 하이라이트 (제목·단계·조건·결과 중 어디서 일치했는지 표시)
2. 실험 상태, 날짜, 프로젝트
3. 필터·정렬

---

### User Flows

**새 실험 → 수행 → 완료 (s1)**
1. 홈에서 + 새 실험
2. 제목·목적·프로젝트·태그 입력 → 생성
3. 절차 탭에서 수행 모드 시작
4. 단계 체크, 메모·수치 입력 → 다음 단계
   - 단계를 건너뛰면 → 완료 때 미완료 목록 경고
5. 조건·결과 입력 → 상태 완료

**지난 실험 찾기 (s2)**
1. 전역 검색창에 키워드 입력
2. 결과 목록에서 하이라이트 확인
   - 결과 없음 → 철자 제안, 필터 해제, 새 실험 만들기 안내
3. 실험 상세 열기

**복제하여 다시 쓰기 (s3)**
1. 실험 상세에서 복제 (또는 템플릿으로 저장)
2. 절차·조건은 유지, 결과는 비워서 새 실험 생성
3. 수행 모드로 진행

---

### Naming Conventions

- **실험**: 노트·기록·과제를 섞어 쓰지 않는다
- **상태**: 준비 / 진행 / 완료
- **절차와 달라진 점**: 화면 표기. 내부 이름은 편차(deviation)
- **복제**: "복사"가 아니라 복제. 결과는 비워진다는 안내를 함께 표시
- **템플릿**: 표준 절차 묶음

---

### Component Reuse Map

- **실험 카드**: 홈, 실험 목록, 검색 결과 (검색에서는 하이라이트 추가)
- **단계 체크 항목**: 수행 모드, 템플릿 편집 (템플릿에서는 체크 없이 편집만)
- **이름-값-단위 입력 행**: 조건·결과 탭, 템플릿의 기본 조건
- **필터 바**: 실험 목록, 검색 결과

---

### Content Growth Plan

- 실험은 계속 쌓이므로 목록은 페이지 나눔과 필터(프로젝트·태그·상태·기간)를 쓴다.
- 오래된 실험은 `완료` 상태에서 기본 목록의 뒤로 보내고, 검색에서는 항상 찾을 수 있게 한다.
- 태그가 늘어나면 설정에서 병합·정리한다.

---

### URL Strategy

- 패턴: `/섹션/항목-id/하위화면` (예: `/experiments/:id/steps`)
- 동적 부분: 실험 ID, 템플릿 ID
- 쿼리: 검색 `?q=`, 필터 `?project=&tag=&status=`, 정렬 `?sort=`
