## Information Architecture: 실험 기록 서비스

**풀려는 문제**: 실험 기록이 여러 곳에 흩어져 찾기도 재현하기도 어려운 문제

**구성 기준**: s1 모으기 → s2 찾기 → s3 다시 쓰기 → s4 살펴보기 → s5 분석(▲ v2)

가정: 사용 기기는 PC와 태블릿이다. (확인 필요) 휴대폰 폭(390px)에서도 깨지지 않는다.

▲ 표시는 lablog v1 IA에서 v2 문서로 바뀐 부분이다. 현재 앱(`app/src/app/routes.tsx`)과 맞췄다.

### Navigation Model

- **Primary navigation**: 홈 · 프로젝트 · 실험 · **데이터(▲)** · 검색 · 템플릿 (6개). 팀은 P2에 추가하면서 템플릿을 설정으로 옮기는 것을 검토한다.
- **Secondary navigation**: 프로젝트 상세 탭 — 현황 / 데이터 / 분석. 실험 상세 탭 — 개요 / 절차 / 조건·결과 / 첨부 / 편차. 실험 목록의 필터(프로젝트·태그·상태·기간).
- **Utility navigation**: 전역 검색창, + 새 실험, 설정, 프로필. 모든 화면 상단에 둔다.
- **Mobile navigation**: 하단 탭(홈·프로젝트·실험·데이터·검색, 템플릿은 더보기). ▲ 수행 모드는 전체 화면. [가정]

### Content Hierarchy

**홈 (대시보드)**
1. 진행 중 실험(남은 단계 수 포함) — 오늘 해야 할 일이라 가장 먼저
2. 놓친 것 — 모든 프로젝트의 빠짐 점검 결과를 심각한 것부터. 프로젝트 이름과 이유를 함께 보여 준다
3. 최근 실험 — 다시 열기 쉽게

**프로젝트 목록**
1. 프로젝트 카드: 이름, 목표, 실험 수와 상태별 개수, 전체 진행률
2. 확인할 것 개수 — 붉은 글씨로 눈에 띄게
3. 최근 활동 시점

**프로젝트 현황**
1. 진행 현황(상태별 막대, 단계 진행률)
2. 빠진 것 한눈에 — 종류, 해당 실험 링크, 이유
3. 타임라인(실험별 시작~완료 막대, 오늘 표시선)
4. 최근 실험

**프로젝트 데이터**
1. 실험 × 항목 표: 같은 이름의 조건·결과를 한 열로, 조건이 결과보다 앞
2. 이상치(▲)와 빈 값(—), 항목 없음(·) 표시
3. CSV 내보내기

**프로젝트 분석**
1. 조건과 결과의 관계(산점도, 상관계수와 풀어 쓴 해석)
2. 실험 순서에 따른 추세(중앙값 표시선)
3. 이상치 후보 목록

**실험 목록**
1. 검색창과 필터 — 찾기가 이 화면의 목적
2. 실험 카드: 제목, 상태, 진행률, 담당자
3. 정렬 (최근 수정순 기본)

**수행 모드 (실험 상세 · 절차)**
1. 현재 단계와 체크 — 수행 중 가장 자주 쓰는 동작
2. 단계 메모·수치 입력 — 체크와 같은 화면에서 해결
3. 전체 진행률, 이전·다음 단계
4. 편차 기록 버튼 (접어 둠)

**검색 결과**
1. 일치한 문구 하이라이트 (제목·단계·조건·결과 중 어디서 일치했는지 표시)
2. 실험 상태, 날짜, 프로젝트
3. 필터·정렬

---

**데이터 허브 (`/data`)** ▲
1. 전체 실험 × 항목 표 — 가장 자주 쓰는 화면이라 먼저
2. 필터(프로젝트·기간·상태)와 숫자 열만 보기
3. 분석·내보내기 탭으로 이동

**로그인** ▲
1. 이메일·비밀번호 입력과 로그인 버튼
2. 이메일 링크 로그인(보조)
3. 오류 안내(틀린 비밀번호, 연결 실패)

### User Flows

**새 실험 → 수행 → 완료 (s1)**
1. 홈에서 + 새 실험
2. 제목·목적·프로젝트·태그 입력 → 생성
3. 절차 탭에서 수행 모드 시작
4. 단계 체크, 메모·수치 입력 → 다음 단계
   - 단계를 건너뛰면 → 완료 때 미완료 목록 경고
5. 조건·결과 입력 → 상태 완료

**지난 실험 찾기 (s2)**
1. 전역 검색창에 키워드 입력
2. 결과 목록에서 하이라이트 확인
   - 결과 없음 → 철자 제안, 필터 해제, 새 실험 만들기 안내
3. 실험 상세 열기

**복제하여 다시 쓰기 (s3)**
1. 실험 상세에서 복제 (또는 템플릿으로 저장)
2. 절차·조건은 유지, 결과는 비워서 새 실험 생성
3. 수행 모드로 진행

---

**프로젝트를 살펴보기 (s4)**
1. 홈의 "놓친 것" 또는 메뉴의 프로젝트에서 프로젝트를 연다
2. 현황의 "빠진 것 한눈에"에서 항목을 눌러 해당 실험으로 가서 채운다
   - 채우면 돌아왔을 때 목록에서 사라진다
   - 의도적인 경우(예: 일부러 건너뜀)는 현재 무시 기능이 없어 목록에 남는다(열린 점)
3. 데이터 탭에서 항목별 표를 확인하고 CSV로 내보낸다
4. 분석 탭에서 가로축·세로축을 골라 관계와 추세를 보고, 점을 눌러 해당 실험을 연다

**새 실험을 이어받아 시작 (s3)**
1. 프로젝트 화면의 "+ 이 프로젝트에 새 실험" 또는 새 실험에서 프로젝트 선택
2. "마지막 실험의 절차와 조건·결과 항목 이어받기"(기본 켬)를 확인하고 제목 입력
3. 절차·조건은 그대로, 결과 값은 빈 채로 만들어져 빠뜨리지 않고 채울 수 있다

### Naming Conventions

- **실험**: 노트·기록·과제를 섞어 쓰지 않는다
- **상태**: 준비 / 진행 / 완료
- **절차와 달라진 점**: 화면 표기. 내부 이름은 편차(deviation)
- **복제**: "복사"가 아니라 복제. 결과는 비워진다는 안내를 함께 표시
- **템플릿**: 표준 절차 묶음

---

### Component Reuse Map

- **실험 카드**: 홈, 실험 목록, 검색 결과 (검색에서는 하이라이트 추가)
- **단계 체크 항목**: 수행 모드, 템플릿 편집 (템플릿에서는 체크 없이 편집만)
- **이름-값-단위 입력 행**: 조건·결과 탭, 템플릿의 기본 조건
- **필터 바**: 실험 목록, 검색 결과

---

### Content Growth Plan

- 실험은 계속 쌓이므로 목록은 페이지 나눔과 필터(프로젝트·태그·상태·기간)를 쓴다.
- 오래된 실험은 `완료` 상태에서 기본 목록의 뒤로 보내고, 검색에서는 항상 찾을 수 있게 한다.
- 태그가 늘어나면 설정에서 병합·정리한다.

---

### URL Strategy

- 패턴: `/섹션/항목-id/하위화면` (예: `/experiments/:id/steps`)
- 동적 부분: 실험 ID, 템플릿 ID
- 쿼리: 검색 `?q=`, 필터 `?project=&tag=&status=`, 정렬 `?sort=`

| 구조 요소 | 쓰이는 곳 | 비고 |

| 앱 셸(내비, 상단바) | 홈·프로젝트·실험·데이터·검색·템플릿·설정·휴지통 | 수행 모드와 로그인은 셸 없음 |

| 표·차트(`DataGrid`, `charts`) | 프로젝트 데이터·분석, 데이터 허브 | 허브는 전체, 프로젝트는 한 프로젝트 |
| 빈 상태·로딩·오류 화면 | 모든 화면 | 전역 규칙 |

### URL Strategy

- 형식: `/섹션/:id/하위`. 실험·프로젝트 id는 UUID.
- 새로고침·직접 주소로 열려야 하므로 모든 경로를 `index.html`로 보낸다(Vercel 설정).
- 필터·정렬은 쿼리 문자열(`?project=…&status=…`)에 둔다.

### Content Growth Plan

- 실험·데이터 항목은 계속 늘어난다(1,000건 이상). 목록은 페이지 단위로 읽고, 표는 한 번에 200줄씩 그린다. 검색은 지금 읽어 온 데이터를 메모리에서 찾고, 수천 건을 넘으면 서버 검색(`pg_trgm`)을 검토한다.
