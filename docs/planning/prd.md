## PRD: lablog-v2 (프로젝트·실험 로그)

**문제**: 기능은 많지만 실험을 편리하게 등록하고 기록의 핵심을 한눈에 파악하는 경험이 중심에 있지 않다. (`문제정의.md`)

확인된 사실만 사실로 쓰고 나머지는 `[가정]`이다.

---

### 1. 요약

개인 연구원이 반복 실험을 편리하게 등록하고, 프로젝트 안에서 실험의 목적·진행·주요 결과를 한눈에 파악하는 실험 로그다. v2는 독립 검색·템플릿 기능을 줄이고 **홈 → 프로젝트 → 실험**의 핵심 흐름에 집중한다.

### 3. 배경

- 현재 앱은 제목만으로 실험 생성, 프로젝트 자동 선택, 마지막 실험 이어받기를 지원한다.
- 그러나 생성 화면에 여러 선택지가 한꺼번에 있고, 목록은 제목·상태·진행률 위주라 실제 조건·결과를 비교하기 어렵다.
- 검색과 템플릿은 주 내비게이션을 차지하지만, 사용자가 원하는 핵심은 빠른 동작보다 반복 입력 부담 감소와 기록 파악이다.
- 구조 재구성 1단계는 완료됐다. 이후 구조 작업은 새 제품 범위를 확정한 뒤 재개한다.

### 4. 목표

**이미 아는 것은 앱이 채우고 사용자는 달라진 것만 입력하며, 기록을 다시 정리하지 않고도 프로젝트 상황을 이해하게 한다.**

핵심 결과:
- KR1. 프로젝트에서 새 실험을 시작해 제목만 입력하면 30초 안에 준비 상태로 저장할 수 있다. `[가정: 30초]`
- KR2. 반복 실험에서 절차·조건·결과 항목을 다시 입력하지 않고, 가져올 항목을 확인한 뒤 달라진 부분만 수정한다.
- KR3. 최근 실험 10건의 상태·진행·주요 조건·결과·수정 시각을 목록에서 10초 안에 파악한다. `[가정: 10초]`
- KR4. 완료 시점의 미완료 단계·빈 결과·단위 불일치가 주마다 줄어든다.
- KR5. 기존 데이터·백업을 잃지 않고 자동 시험 기준선과 구조 규칙을 유지한다.

지켜야 할 선: 사용자가 같은 내용을 두 번 입력하지 않는다. 입력 중이던 내용이 사라지지 않는다. 이전 실험의 결과 값이 새 실험에 남지 않는다.

### 5. 시장 세그먼트

첫 버전은 개인 연구원 한 그룹이다.
- **반복 실험을 수행하는 연구원**: 여러 프로젝트를 병행하고, 이전 조건을 바꿔 다음 실험을 만든다.
- 제약: 실험대에서 장갑을 끼고 PC·태블릿을 쓸 수 있다 `[가정]`. 팀 공유는 이번 범위 밖이다.

### 6. 가치 제안

**Who**: 여러 프로젝트와 반복 실험을 병행하는 개인 연구원

**Why**: 실험을 빠뜨리지 않고 기록하며, 지난 결과를 다시 정리하지 않고 다음 조건을 정하고 싶다.

**What before**: 종이·엑셀·메모를 오가며 같은 절차와 조건을 다시 쓰고, 상세 기록을 하나씩 열어 결과를 비교한다.

**How**: 프로젝트 맥락과 이전 실험을 자동으로 연결하고, 달라진 부분만 입력하게 하며, 목록과 개요에서 핵심 기록을 요약한다.

**What after**: 반복 입력 없이 실험을 시작하고, 프로젝트의 최근 결과와 빠진 기록을 바로 파악한다.

**Alternatives**: 종이 노트, 엑셀, 메모 앱. lablog는 수행 기록과 프로젝트 맥락이 연결되고 누락을 바로 알려 준다는 점으로 구분한다.

**한 줄**: 이전 실험에서 달라진 것만 기록하면, 프로젝트의 진행과 결과가 한눈에 보입니다.

### 7. 솔루션

**7.1 핵심 흐름**

`프로젝트 열기 → 새 실험 → 시작 방법 선택 → 달라진 부분 확인 → 수행 → 결과 기록 → 프로젝트에서 최근 결과 확인`

주 내비게이션은 홈·프로젝트·실험·데이터 4개다. 검색과 템플릿은 주 내비게이션과 독립 화면에서 제거한다.

**7.2 핵심 기능**

- **편리한 실험 등록(Must)**: 프로젝트 자동 선택, 제목 제안, 제목만으로 생성, 빈 실험/마지막 실험/기존 실험에서 시작.
- **선택해서 이어받기(Must)**: 절차·조건·결과 항목 중 가져올 범위를 명확히 보여 준다. 결과 값·단계 체크·메모는 복사하지 않는다.
- **한눈에 보는 실험 목록(Must)**: 상태·진행·프로젝트·주요 조건·결과·편차·수정 시각을 밀도 높은 행으로 표시한다. 키워드·프로젝트·상태·기간 필터를 같은 화면에 둔다.
- **한눈에 보는 실험 개요(Must)**: 목적, 진행률, 주요 조건·결과, 편차와 다음 행동을 첫 화면에 배치한다. 결론·다음 행동의 저장 방식은 확인 필요다.
- **프로젝트 현황(Must)**: 진행 중 실험, 최근 완료 실험의 주요 결과, 빠진 기록, 새 실험 진입점을 먼저 보여 준다.
- **수행과 기록(Must)**: 큰 터치 영역, 즉시 저장 표시, 미완료·빈 결과 안내, 오류 후 복구를 유지한다.
- **데이터·분석(Should)**: 프로젝트 데이터와 현재 데이터 허브는 유지하되 이번 작업에서는 고급 통계를 확장하지 않는다.
- **계정·백업(Must)**: 로그인, 로컬/서버 저장, 가져오기·내보내기와 기존 데이터 호환을 유지한다.

**7.3 기술**

기존 TypeScript·React·Vite·Supabase·Vercel 스택을 유지한다. 새 라이브러리는 추가하지 않는다.

**7.4 가정과 열린 질문**

1. `[확인 필요]` 명시적인 결론·다음 행동을 실험 필드로 추가할지. 추가하면 DB 마이그레이션이 필요하다.
2. `[가정]` 기존 템플릿은 화면에서 제거하되 데이터와 백업에서는 보존한다.
3. `[가정]` 전역 본문 검색 없이 실험 목록의 제목·목적 키워드와 필터로 첫 범위를 충족한다.
4. `[확인 필요]` 주요 조건·결과는 최근/앞쪽 항목을 자동 표시할지 사용자가 고를지.
5. 실험대 입력 환경과 목표 시간은 직접 QA로 검증한다.

### 8. 출시

- **첫 범위**: 편리한 실험 등록, 선택적 이어받기, 실험 목록·개요 요약, 프로젝트 현황 집중, 별도 검색·템플릿 UI 제거.
- **유지**: 수행 모드, 조건·결과, 편차, 빠짐 점검, 데이터·분석, 로그인, 백업·이전, 휴지통.
- **나중에**: 전역 본문 검색, 표준 절차 관리가 실제로 필요하다는 근거가 생기면 다시 설계한다. 팀 공유·첨부·자동 동기화도 이후 범위다.
- **하지 않음**: 기존 템플릿 데이터 삭제, 장비 연동, 시약 재고·발주, 전자서명·규제 대응, 고급 통계 확장.
- **진행 순서**: 새 spec 확정 → 구현 계획 확정 → 핵심 경험 구현 → 축소된 코드 기준으로 구조 재구성 재개.
