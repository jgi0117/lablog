## PRD: 실험 기록 서비스

**문제**: 실험 기록이 여러 곳에 흩어져 찾기도 재현하기도 어려운 문제

확인된 사실만 사실로 쓰고, 나머지는 [가정]으로 표시했습니다. 예시는 필름 제품 개발(하드코팅, 방현, 유연 코팅) 업무를 기준으로 합니다.

---

### 1. 요약

맡은 프로젝트의 실험 기록을 빠뜨리지 않고 한곳에 모으고, 한눈에 보게 돕는 개인 연구원용 실험 노트입니다. 지금은 기록이 흩어져 있어 지난 실험을 찾기 어렵고, 단계나 결과를 빠뜨려 실험을 다시 하는 일이 생깁니다. 여러 실험의 결과를 비교하려면 엑셀에 다시 모아야 합니다. [가정] 이 서비스는 기록하는 순간부터 프로젝트 단위로 모이게 하고, 무엇이 빠졌는지와 결과가 어떻게 움직이는지를 바로 보여 줍니다.

### 3. 배경

- 연구원은 실험마다 절차·조건·결과를 적습니다. 기록 수단은 종이 노트, 엑셀, 메모 앱, 메신저로 사람마다 다릅니다. [가정]
- 체크리스트가 여러 앱에 흩어져 어디에 적었는지 못 찾는 문제는 확인됐습니다(일반 사용자 기준). 실험실에서도 같은지는 아직 확인하지 않았습니다.
- 여러 프로젝트를 병행하는 사원은 어느 실험의 결과를 안 적었는지, 어떤 조건을 빠뜨렸는지 스스로 알아채기 어렵습니다. [가정]
- 조건과 결과의 관계(예: 건조 온도에 따른 경도)를 보려면 기록을 엑셀로 다시 옮겨야 합니다. [가정]
- 원인 후보: 기록 위치가 제각각, 절차가 머릿속과 말로 전해짐, 전용 도구와 표준 양식이 없음. [가정]

### 4. 목표

**맡은 프로젝트의 실험을 빠뜨리지 않고 모으고, 한눈에 본다.**

핵심 결과
- KR1. 지난 실험을 검색해서 **10초 안에** 연다.
- KR2. 단계를 빠뜨려서 다시 하는 실험이 도입 전보다 **줄어든다.** (먼저 현재 수치를 잰다)
- KR3. 프로젝트 화면의 "빠진 것"이 쌓이지 않고 **주마다 줄어든다.** (결과 없이 완료, 빈 결과, 멈춘 실험, 빠진 항목)
- KR4. 파일럿 참여자의 **80%가 주 1회 이상** 프로젝트 화면을 연다.

지켜야 할 선: 기록하는 시간이 지금보다 늘지 않는다.

### 5. 시장 세그먼트

첫 버전은 두 그룹에 집중합니다.
- **연구원(사원)**: 여러 프로젝트를 병행하며 자기 실험을 스스로 정리하고, 장갑을 낀 채 실험대에서 작업합니다. 제약: 수행 중 기기 입력이 가능한지 아직 모릅니다.
- **신규 입사자**: 선배의 실험을 같은 조건으로 따라 하려는 사람입니다.

팀장·PI와 팀 공유 기능은 다음 버전에서 다룹니다. 이 서비스는 개인이 자기 프로젝트를 챙기는 도구로 시작합니다.

### 6. 가치 제안

**연구원**
- **Who**: 여러 프로젝트를 병행하는 연구원
- **Why**: 맡은 프로젝트를 빠뜨림 없이 정리하고, 데이터를 한곳에 모아 흐름을 보고 싶다
- **What before**: 종이에 적고 나중에 엑셀에 옮긴다. 기록이 여기저기 있어 못 찾고, 무엇을 안 적었는지 모른다. 결과를 비교하려면 표를 다시 만든다.
- **How**: 실험 하나에 절차·조건·결과를 모으고, 프로젝트로 묶어 현황과 빠진 것을 보여 주며, 데이터를 표와 차트로 보여 준다
- **What after**: 다시 옮겨 적지 않고, 빠진 것을 그날 알아채고, 조건과 결과의 관계를 바로 본다
- **Alternatives**: 종이 노트, 엑셀, 메모 앱, 메신저. 이 서비스는 기록·점검·비교를 한 곳에서 한다.
- **한 줄**: 맡은 프로젝트의 실험을 빠뜨리지 않고 모아, 한눈에 보게 해 줍니다.

**신규 입사자**
- **Who**: 선배의 실험을 따라 하는 신규 입사자
- **Why**: 같은 조건으로 실수 없이 하고 싶다
- **What before**: 선배에게 묻거나 불완전한 노트를 읽고 짐작한다
- **How**: 같은 프로젝트의 마지막 실험을 이어받아 절차·조건·결과 항목을 그대로 쓴다
- **What after**: 처음부터 쓰지 않고, 선배 도움이 적어도 같은 조건으로 시작한다
- **Alternatives**: 선배에게 직접 묻기, 노트 사진 받기
- **한 줄**: 마지막 실험을 이어받아 같은 조건으로 시작합니다.

KR2(재실험 감소)는 연구원의 "무엇을 안 적었는지 모른다"를, KR3은 "그날 알아챈다"를, KR1은 "검색 한 번에 연다"를 잽니다.

### 7. 솔루션

**7.1 화면과 흐름**
핵심 흐름은 네 가지입니다. (1) 새 실험을 수행한다, (2) 지난 실험을 찾는다, (3) 이전 실험을 이어받아 다시 쓴다, (4) 프로젝트를 살펴본다. 화면 구조는 IA.md, 단계별 감정과 오류 처리는 uj.md에 있습니다.

**7.2 핵심 기능** (첫 버전은 s1, s2, s4와 s3의 이어받기)

s1. 모으기 — Must
- 실험 만들기: 제목·목적·담당자, 프로젝트와 태그
- 절차 체크리스트: 한 화면에서 체크와 메모·수치 입력 (수행 모드)
- 조건·결과: 이름-값-단위로 입력, 숫자 아님·자릿수 이상 경고

s2. 찾기 — Must
- 분류: 프로젝트·태그·상태(준비/진행/완료)
- 실험 목록과 통합 검색: 제목·단계·조건·결과를 모두 검색, 일치 위치 표시
- 첨부(사진·파일): Should

s3. 다시 쓰기
- 이전 실험 이어받기: 절차와 조건, 결과 항목 이름을 가져오고 결과 값은 비움 — Must (빠뜨림 방지)
- 템플릿, 절차와 달라진 점(편차) 기록 — Should (다음 버전)
- 팀 대시보드, 가져오기 — Could

s4. 살펴보기 — Must (신규)
- 프로젝트 화면: 맡은 프로젝트별 실험 수, 진행률, 최근 활동, 타임라인
- **빠짐 점검**: 결과 없이 완료한 실험, 빈 결과, 미완료 단계가 남은 완료 실험, 오래 멈춘 실험(진행 7일, 준비 14일), 같은 프로젝트의 다른 실험에는 있는 조건·결과 항목이 빠진 실험, 단위가 섞인 항목. 홈에서도 모든 프로젝트의 빠진 것을 모아 보여 줍니다.
- **데이터 표**: 프로젝트의 모든 실험을 항목별로 한 표에 모으고 CSV로 내보내기
- **차트**: 조건과 결과의 관계(산점도와 상관계수), 실험 순서에 따른 추세, 프로젝트 타임라인, 상태별 개수
- **이상치 후보**: 같은 항목의 다른 값과 크게 다른 값을 표시. 후보일 뿐이며 사용자가 확인합니다.
- 항목 이름이 같아야 한 열로 묶이므로, 같은 이름·단위로 입력하도록 안내합니다(자동 완성, 단위 불일치 표시).

**7.4 가정과 열린 질문**
1. 기록이 여러 도구에 흩어져 있다 → 연구원 3~5명에게 최근 실험 기록 위치를 묻는다
2. 재실험 상당수가 단계 누락·조건 오기록 때문이다 → 최근 재실험 5건의 이유를 나눠 본다
3. 수행 중 디지털 기기로 입력할 수 있다 → 실험대 환경을 관찰한다
4. 외부 클라우드에 저장해도 된다 → 기관 보안 정책을 확인한다
5. **개인이 맡은 프로젝트를 정리하고 비교하고 싶어 한다** → "여러 실험의 결과를 한곳에서 비교하고 싶은 때가 있나요?", "무엇을 안 적었는지 어떻게 알아채나요?"를 인터뷰에서 묻는다
6. 빠짐 점검 기준(진행 7일·준비 14일, 다른 실험 절반 이상이 쓰는 항목, 이상치 기준)이 현장에 맞다 → 파일럿에서 오탐을 기록해 조정한다
7. 연구원이 조건·결과 이름을 일관되게 쓴다 → 자동 완성과 단위 표시가 충분한지 파일럿에서 확인한다
- 열린 질문: 프로젝트마다 목표 사양(예: 투과율 90% 이상)을 두고 달성 여부를 보여 줄까? 기존 엑셀을 가져올 필요가 있나? 로그인·권한은 어디까지?

### 8. 출시

- **첫 버전**: s1 전체, s2의 분류·통합 검색, s3의 이어받기, s4 전체
- **나중에**: 첨부, 템플릿, 편차 기록 → 목표 사양 표시, 가져오기 → 팀 대시보드
- **하지 않음**: 통계 모형(회귀 분석, 가설 검정 등), 장비 연동, 시약 재고·발주, 전자서명·규제 대응
