## PRD: lablog-v2 (실험 노트 리뉴얼)

**문제**: 기능은 늘었는데 구조와 문서가 따라오지 못해 다음 기능을 안전하게 얹기 어렵다. (`문제정의.md`)

확인된 사실만 사실로 쓰고 나머지는 `[가정]`이다. lablog v1의 PRD와 달라진 곳은 ▲로 표시했다.

---

### 1. 요약

개인 연구원이 실험의 절차·조건·결과를 빠뜨리지 않고 기록하고, 쌓인 기록을 찾고 분석하는 실험 노트다. v2는 새 기능을 더하는 것이 아니라 **v1의 모든 기능을 유지한 채 구조를 클린 아키텍처로 재구성하고, 문서를 앱과 일치시키는** 리뉴얼이다. 지금 하는 이유는 로그인·서버 저장소·통계가 붙으면서 300줄 넘는 파일이 9개로 늘었고, 문서가 앱과 달라졌기 때문이다.

### 3. 배경

- v1은 Phase 0~9를 거쳐 기록·검색·프로젝트 현황·고객 요구 판정·데이터 허브·통계·서버 저장소·로그인까지 갖췄다. 직접 QA 21개 중 19개 통과, 1개 실패(두 탭 충돌 안내), 1개 미실행.
- 구조 부채: 큰 파일, 계층형 폴더, 저장소 구현 두 벌. 문서 부채: PRD·IA·UJ가 로그인·데이터 허브·통계를 반영하지 않음.
- 파일럿 사용자는 개발팀 개인 1명이다. 기기는 정하지 않았다. [가정]

### 4. 목표

**v1과 같은 일을 하되, 안전하게 고치고 늘릴 수 있는 구조로 만든다.**

핵심 결과
- KR1. 지난 실험을 검색해서 10초 안에 연다. (v1 유지)
- KR2. 빠짐 점검의 "빠진 것"이 주마다 줄어든다. (v1의 KR3 유지)
- KR3. ▲ 모든 코드 파일이 300줄 이하이고 import 경계 위반이 0건이다(린터가 검사).
- KR4. ▲ 기존 시험 450개와 E2E 112개가 재구성 단계마다 통과하고, 기존 시험은 고치지 않는다.
- KR5. ▲ PRD·IA·UJ·ERD가 현재 앱과 일치한다(점검표 통과).

지켜야 할 선: 기록하는 시간이 늘지 않는다. 데이터를 잃지 않는다.

### 5. 시장 세그먼트

첫 버전은 개인 연구원 한 그룹이다.
- **연구원(개인)**: 여러 프로젝트를 병행하며 자기 실험을 정리하고 분석한다. 장갑을 끼고 실험대에서 쓰기도 한다. 제약: 수행 중 기기 입력 가능 여부는 미확인 `[가정]`.
- 신규 입사자(마지막 실험 이어받기)는 v1 기능으로 유지하지만 별도 세그먼트로 설계하지 않는다.
- ▲ 팀장·팀 공유는 이번 범위가 아니다. 구조(`owner_id` + RLS)만 확장 가능하게 둔다.

### 6. 가치 제안

**연구원**
- **Who**: 여러 프로젝트를 병행하는 연구원
- **Why**: 실험을 빠뜨림 없이 기록하고, 쌓인 데이터를 찾고 분석하고 싶다
- **What before**: 종이·엑셀·메모에 흩어진 기록, 무엇을 안 적었는지 모름, 결과 비교 때 표를 다시 만듦
- **How**: 실험 하나에 절차·조건·결과를 모으고, 프로젝트로 묶어 현황·빠짐·고객 요구 달성을 보여 주며, 데이터 허브로 표·통계·내보내기를 제공한다
- **What after**: 다시 옮겨 적지 않고, 빠진 것을 그날 알고, 조건과 결과의 관계를 바로 본다
- **Alternatives**: 종이 노트, 엑셀, 메모 앱
- **한 줄**: 맡은 프로젝트의 실험을 빠뜨리지 않고 모아, 한눈에 보고 분석하게 해 줍니다.

(리뉴얼의 가치는 같은 가치를 **더 안전하게 고칠 수 있게** 하는 것이다. 사용자에게 보이는 변화는 최소로 한다.)

### 7. 솔루션

**7.1 화면과 흐름**: 구조는 `IA.md`, 여정은 `uj.md`. 주 내비는 홈·프로젝트·실험·검색·템플릿·**데이터**(▲ 6개).

**7.2 핵심 기능** (v1 전부 유지)
- s1 모으기(Must): 실험 만들기, 절차 체크리스트(수행 모드), 조건·결과 입력과 경고
- s2 찾기(Must): 프로젝트·태그·상태 분류, 목록·통합 검색
- s3 다시 쓰기: 마지막 실험 이어받기(Must), 템플릿, 달라진 점(편차) 기록
- s4 살펴보기(Must): 프로젝트 현황, 빠짐 점검, 데이터 표·CSV, 차트, 이상치 후보, 고객 요구 특성 달성 판정
- ▲ s5 분석: 데이터 허브(전체 실험 표, 상관·회귀·분산분석·히스토그램, 내보내기). v1에서 PRD 범위 밖이던 것을 정식 범위로 인정한다.
- 계정·저장: 서버 저장소(Supabase) + 로그인(개인용, 가입 닫기, 표시 이름), 로컬 저장소 모드(오프라인), 백업 가져오기·내보내기, 이전 마법사

**7.3 기술**: TypeScript + React + Vite, Supabase(서울), Vercel. 구조는 `docs/adr/0002`, 저장소 어댑터는 `docs/adr/0003`.

**7.4 가정과 열린 질문**
1. 기관 보안 정책상 외부 클라우드 저장이 가능하다 → 확인 필요(사용자, 기관).
2. 두 탭 충돌 안내 실패(QA 13번)는 코드 결함이다 → v2 서버 저장소 계약 시험으로 재현한다.
3. 수행 중 디지털 기기로 입력할 수 있다 → 실험대 환경 관찰.
4. 빠짐 점검 기준(진행 7일·준비 14일 등)이 현장에 맞다 → 파일럿에서 오탐을 기록한다.
- 열린 질문: 오프라인(로컬) 기록을 서버로 자동 동기화할까? (이번엔 안 함, 백업 이동만)

### 8. 출시

- **v2 첫 출시**: v1 기능 전체 + 구조 재구성(5단계, `specs/001`) + 문서 일치 + lablog 데이터 이전
- **나중에**: 팀 공유, 첨부(사진·파일), 오프라인 자동 동기화, 엑셀 가져오기
- **하지 않음**: 장비 연동, 시약 재고·발주, 전자서명·규제 대응. ▲ (통계 분석은 "하지 않음"에서 뺐다. 범위는 구현된 상관·회귀·분산분석·히스토그램까지.)
- **기간**: 기한 없이 단계별 완료로 진행한다.
