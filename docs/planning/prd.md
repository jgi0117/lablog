## PRD: 실험 기록 서비스

**문제**: 실험 기록이 여러 곳에 흩어져 찾기도 재현하기도 어려운 문제

확인된 사실만 사실로 쓰고, 나머지는 [가정]으로 표시했습니다.

---

### 1. 요약

여러 실험을 함께 하는 연구원이 실험 기록을 한 곳에 모으고, 분류하고, 검색해서 다시 쓰게 돕는 서비스입니다. 지금은 기록이 흩어져서 지난 실험을 찾기 어렵고, 단계를 빠뜨려 실험을 다시 하는 일이 생깁니다. [가정] 빠르게 쓸 수 있는 첫 버전으로 이 문제가 실제인지 확인하고 줄입니다.

### 3. 배경

- 연구원은 실험마다 절차·시약·조건·결과를 적습니다. 기록 수단은 종이 노트, 엑셀, 메모 앱, 메신저로 사람마다 다릅니다. [가정]
- 체크리스트가 여러 앱에 흩어져 어디에 적었는지 못 찾는 문제는 확인됐습니다(일반 사용자 기준). 실험실에서도 같은지는 아직 확인하지 않았습니다.
- 원인 후보: 기록 위치가 제각각, 절차가 머릿속과 말로 전해짐, 전용 도구와 표준 양식이 없음. [가정]

### 4. 목표

**실험 단위로 모으고 → 분류하고 → 검색·재사용한다.**

핵심 결과
- KR1. 지난 실험을 검색해서 **10초 안에** 연다.
- KR2. 단계를 빠뜨려서 다시 하는 실험이 도입 전보다 **줄어든다.** (먼저 현재 수치를 잰다)
- KR3. 파일럿 팀의 **80%가 주 1회 이상** 쓴다.

지켜야 할 선: 기록하는 시간이 지금보다 늘지 않는다.

### 5. 시장 세그먼트

첫 버전은 두 그룹에 집중합니다.
- **연구원**: 3~4개 실험을 함께 진행하고, 장갑을 낀 채 실험대에서 작업합니다. 제약: 수행 중 기기 입력이 가능한지 아직 모릅니다.
- **신규 입사자**: 선배의 실험을 같은 조건으로 따라 하려는 사람입니다.

팀장/PI는 다음 버전에서 다룹니다.

### 6. 가치 제안

**연구원**
- **Who**: 여러 실험을 병행하는 연구원
- **Why**: 실험을 빠뜨림 없이 하고, 필요할 때 지난 기록을 찾고 싶다
- **What before**: 종이에 적고 나중에 엑셀에 옮긴다. 기록이 여기저기 있어 못 찾는다.
- **How**: 실험 하나에 절차·조건·결과를 모으고, 한 화면에서 체크와 메모를 하며, 검색으로 찾는다
- **What after**: 다시 옮겨 적지 않고, 검색 한 번에 지난 실험을 연다
- **Alternatives**: 종이 노트, 엑셀, 메모 앱, 메신저. 이 서비스는 한 곳에서 체크·기록·검색을 모두 한다.
- **한 줄**: 실험 기록을 한 곳에 모아, 찾고 다시 하는 시간을 줄여 줍니다.

**신규 입사자**
- **Who**: 선배의 실험을 따라 하는 신규 입사자
- **Why**: 같은 조건으로 실수 없이 하고 싶다
- **What before**: 선배에게 묻거나 불완전한 노트를 읽고 짐작한다
- **How**: 선배의 실험을 복제해서 절차와 조건을 그대로 쓴다
- **What after**: 처음부터 쓰지 않고, 선배 도움이 적어도 같은 조건으로 시작한다
- **Alternatives**: 선배에게 직접 묻기, 노트 사진 받기
- **한 줄**: 선배의 실험을 그대로 복제해 같은 조건으로 시작합니다.

KR2(재실험 감소)는 연구원의 "What after"를, KR1은 "검색 한 번에 연다"를 잽니다.

### 7. 솔루션

**7.1 화면과 흐름**
핵심 흐름은 세 가지입니다. (1) 새 실험을 수행한다, (2) 지난 실험을 찾는다, (3) 복제해서 다시 쓴다. 화면 구조는 IA.md, 단계별 감정과 오류 처리는 uj.md에 있습니다.

**7.2 핵심 기능** (첫 버전은 s1, s2)

s1. 모으기 — Must
- 실험 만들기: 제목·목적·담당자
- 절차 체크리스트: 한 화면에서 체크와 메모·수치 입력 (수행 모드)
- 조건·결과: 이름-값-단위로 입력

s2. 찾기 — Must
- 분류: 프로젝트·태그·상태(준비/진행/완료)
- 실험 목록과 통합 검색: 제목·단계·조건·결과를 모두 검색
- 첨부(사진·파일): Should

s3. 다시 쓰기 — Should 이하 (다음 버전)
- 복제·템플릿: 절차·조건은 그대로, 결과는 비움
- 절차와 달라진 점(편차) 기록
- 팀 대시보드, 가져오기: Could

**7.4 가정과 열린 질문**
1. 기록이 여러 도구에 흩어져 있다 → 연구원 3~5명에게 최근 실험 기록 위치를 묻는다
2. 재실험 상당수가 단계 누락·조건 오기록 때문이다 → 최근 재실험 5건의 이유를 나눠 본다
3. 수행 중 디지털 기기로 입력할 수 있다 → 실험대 환경을 관찰한다
4. 외부 클라우드에 저장해도 된다 → 기관 보안 정책을 확인한다
5. 개인 노트와 팀 공유 중 무엇이 먼저인가 → 인터뷰로 확인한다
- 열린 질문: 연구 분야와 규제 수준은? 기존 도구와 함께 쓸지 바꿀지? 로그인·권한은 어디까지?

### 8. 출시

- **첫 버전**: s1 전체, s2의 분류·통합 검색
- **나중에**: 첨부, 복제·템플릿, 편차 기록 → 팀 대시보드, 가져오기
- **하지 않음**: 장비 연동, 시약 재고·발주, 전자서명·규제 대응, 데이터 분석

**대략적인 기간**
- 1주: 가정 1~3 확인
- 2주: 화면 설계
- 3~4주: s1, s2 만들기
- 5주: 파일럿 1팀 운영, KR 측정
- 6주 이후: s3 범위 결정
