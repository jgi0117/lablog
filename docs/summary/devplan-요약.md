## 개발 계획 요약

**문제**: 실험 기록이 여러 곳에 흩어져 찾기도 재현하기도 어려운 문제

**저장**: 지금은 브라우저 로컬 저장, 나중에 Supabase로 이전
**스택 (제안)**: React + TypeScript + IndexedDB
**핵심 설계**: 화면은 Repository 인터페이스만 부른다. 로컬 구현을 나중에 Supabase 구현으로 교체한다.

**단계**
- **0. 준비**: 스택 확정, 연구원 인터뷰, 샘플 기록 수집
- **1. 설계**: 와이어프레임(수행 모드 우선), 데이터 모델
- **2. 기반 구축**: 프로젝트 뼈대, 저장소 계층, CI
- **3. s1 모으기**: 실험 만들기, 수행 모드(체크·메모 한 화면), 조건·결과
- **4. s2 찾기**: 목록·필터, 통합 검색(10초 안에 열기)
- **4.5 s4 살펴보기**: 프로젝트 화면, 빠짐 점검, 데이터 표·CSV, 차트, 이상치 후보, 항목 자동 완성 (안정화보다 먼저)
- **5. 안정화**: JSON 내보내기·가져오기·백업 알림, 저장 실패·여러 탭 충돌 처리, 접근성(색 대비 자동 검사), 사용 기록(KR 측정)
- **6. 최종 테스트**: 단위·통합·E2E, 연구원 사용성 테스트, 출시 판정
- **7. 파일럿 출시**: 1팀 운영, KR 측정
- **8. s3 다시 쓰기**: 복제·템플릿 → 편차 기록 → 팀 대시보드
- **9. Supabase 전환**: 로그인·RLS, 로컬 데이터 이전, 기능 플래그로 단계 전환

**주요 위험**: 로컬 데이터 유실 → 백업 기능 / 현장 입력 불편 → 목업 검증

**바로 시작**: 스택 확정 → 인터뷰 요청 → 프로젝트 생성 → 수행 모드 와이어프레임
