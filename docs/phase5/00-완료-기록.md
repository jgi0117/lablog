# Phase 5 완료 기록: 안정화

상태: **구현 완료** (실기기 확인 3건이 남음)

## 목표

이 앱의 데이터는 브라우저 안에만 있다. 그래서 가장 큰 위험은 데이터가 사라지는 것이고, 그다음은 여러 탭·저장 실패·접근성이다. 이 단계에서는 "잃지 않게, 잃기 전에 알리게, 같이 쓰는 도구와 부딪히지 않게"를 만들었다.

## 만든 것

**백업과 복원** (설정 화면 `/settings`, `services/backup.ts`)
- 전체 데이터를 JSON 파일로 내보내기. 파일 이름에 날짜와 시각(`lablog-backup-2026-10-19-1432.json`).
- **가져오기 전에 반드시 검사**한다. JSON 여부, 버전(더 새로운 파일은 거부), 필수 값(제목, 상태, 구분, 수정 시각), id 중복, 주인 없는 단계·조건·결과, 파일 크기(100MB)를 보고 사람이 이해할 수 있는 이유를 알려 준다. 알려진 필드만 골라 담아서 파일에 이상한 필드가 섞여도 저장소에 들어가지 않는다.
- 미리보기(프로젝트·실험·단계·조건·결과 개수, 내보낸 때)를 보고 **합치기**(같은 항목은 더 최근에 고친 쪽 유지) 또는 **바꾸기**(전부 지우고 파일 내용으로)를 고른다.
- 바꾸기는 확인창을 거치고, **먼저 현재 데이터를 자동으로 백업 파일로 저장**한다. 그 백업이 실패하면 가져오기를 멈추고 아무것도 바꾸지 않는다.
- **백업 알림**(홈): 한 번도 백업하지 않았고 첫 기록이 하루 넘었거나, 마지막 백업 뒤 바뀐 것이 있고 7일이 지났을 때. "지금 백업", "3일 뒤에 다시".

**저장소 상태** (`app/StorageStatus.tsx`, `services/storage.ts`)
- 앱을 열 때 저장소가 열리는지 확인한다. 못 열면(사생활 보호 모드, 사이트 데이터 차단) 모든 화면 위에 "지금 입력하는 내용은 남지 않습니다"를 띄운다.
- 브라우저에 영구 저장을 요청하고 결과를 설정에 보여 준다. 사용량이 한도의 80%를 넘으면 경고와 "지금 백업".
- 입력 저장이 실패하면 "다시 시도"와 "데이터 내보내기"를 함께 보여 준다. 저장이 안 되는 상황에서도 읽기와 내보내기는 될 수 있다.

**여러 탭** (`services/changeBus.ts`, 저장할 때 version 비교)
- 같은 브라우저의 다른 탭에서 데이터가 바뀌면 "이 화면은 이전 내용일 수 있습니다. 새로 고침" 안내(BroadcastChannel). 지원하지 않는 브라우저에서는 조용히 넘어간다.
- 같은 항목을 두 탭에서 고치면, 나중에 저장하는 쪽에 "다른 탭에서 먼저 수정했습니다. 최신 내용 불러오기 / 내 내용으로 덮어쓰기"가 뜬다. 조용히 덮어쓰지 않는다. 개요, 프로젝트, 단계, 조건·결과, 수행 모드 메모에 모두 적용.

**데이터베이스 마이그레이션**
- DB를 v2로 올렸다(프로젝트별 최근순 복합 인덱스, 예전 기록에 빠진 필드 채우기). 배포된 v1을 그대로 재현해 v1 데이터가 보존되고 새 인덱스가 되는지 테스트한다. 앞으로 스키마를 바꿀 때 따라 할 경로가 생겼다.

**오류 처리**
- 오류 경계: 화면 하나가 깨져도 메뉴와 검색은 남고, 안내와 "다시 시도 / 새로고침 / 데이터 내보내기"를 보여 준다. 앱 전체를 감싸는 경계는 마지막 안전망. 다른 화면으로 이동하면 자동으로 풀린다.
- 오류 기록: 처리하지 못한 오류와 거절된 약속까지 이 기기에 남기고(최근 30건, 앞부분만) 설정에서 보고 지울 수 있다.

**접근성**
- "본문으로 건너뛰기" 링크, 포커스 표시, 라벨, 차트의 스크린 리더 요약과 키보드 조작.
- **색 대비를 자동으로 검사**한다(WCAG AA, 토큰 조합 26개). 처음에는 힌트 글자(`ink-3`)와 경고색이 기준(4.5:1)에 못 미쳤다(3.3~4.1). 어둡게 조정했고, 앞으로 토큰 색을 바꾸면 테스트가 먼저 알려 준다.
- 수행 모드의 화면 꺼짐 방지를 설정에서 끌 수 있다.

**성능**
- 홈과 프로젝트가 실험마다 따로 읽던 방식을 전체 한 번 읽기로 바꿨다. 500건·단계 4,000개에서 묶음 읽기 22ms, 검색은 처음 26ms 이후 3ms(테스트 환경).
- 코드 분할: 프로젝트·차트·설정 화면은 열 때 불러온다. 처음 화면 번들이 줄었다.

**사용 기록(KR 측정)** (`services/usage.ts`)
- 이 기기에만, 시간과 개수만 남긴다. 검색 후 실험을 열기까지 걸린 시간(KR1), 단계 체크, 완료할 때 남은 미완료 단계·빈 결과 수, 빠진 것 개수(6시간에 한 번, KR3의 주별 추이), CSV·백업 내보내기.
- 설정에서 요약(검색 후 열기 중앙값, 10초 안 비율, 완료할 때 빠진 것이 남은 비율, 이번 주·지난주 빠진 것)을 보고, 끄고, 파일로 내보내고, 지울 수 있다. 제목·값·메모는 기록하지 않고 어디로도 전송하지 않는다.

- `npm run check`: 린트, 타입 검사, 테스트 17개 파일 **221개 모두 통과**
- 새 테스트: 백업 검사 12건(깨진 파일, 버전, 필수 값, 중복, 주인 없는 단계, 알 수 없는 필드, 크기), 백업 알림, 저장 공간, 사용 기록, 오류 기록, 변경 알림, 마이그레이션 4건, 설정 통합 22건(내보내기→가져오기 왕복, 바꾸기 확인과 자동 백업과 실패 시 중단, 저장소 차단·용량 경고, 두 탭 충돌과 덮어쓰기, 오류 경계), 색 대비 26건
- 실제 브라우저(개발 서버)에서 홈의 백업 알림과 설정 화면을 확인. 영구 저장은 이 브라우저에서 "허용되지 않음"으로 나왔고, 앱이 그 이유와 백업을 안내했다. 오류 기록 0건.

## 알려진 사항

- **영구 저장은 브라우저가 정한다.** Chrome은 사이트를 자주 쓰거나 홈 화면·북마크에 추가했을 때 허용하는 경향이 있다. 허용되지 않아도 앱은 동작하지만, 파일럿 참여자에게는 "주 1회 백업"을 안내해야 한다. 홈의 백업 알림이 그 역할을 한다.
- **백업은 사람이 눌러야 한다.** 자동 백업(파일 시스템 접근)은 브라우저 지원이 제한적이라 넣지 않았다. 기기를 바꿀 때 가져오기로 옮긴다.
- **다른 기기 간 동기화는 없다.** Supabase 전환(Phase 9)에서 다룬다. 지금은 파일로 옮긴다.
- 여러 탭 알림은 같은 브라우저 안에서만 동작한다.
- 린트 경고 15건(동작 영향 없음): 컴포넌트와 훅을 한 파일에서 내보냄, effect 안의 setState, 렌더 중 `Date`, `componentDidUpdate`의 setState(오류 경계의 화면 이동 시 해제).
- 사용 기록의 "검색 후 열기" 시간은 사용자가 결과를 읽는 시간을 포함한다. 순수한 시스템 속도가 아니라 사람이 찾는 데 걸린 시간이다.
