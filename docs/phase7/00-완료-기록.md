# Phase 7 완료 기록: 가벼운 배포

상태: **준비 완료, 실제 배포는 저장소 설정 한 번이 남음.** 개발팀 1명이 혼자 쓰는 파일럿이라 팀 운영 항목은 건너뛰었다.

## 한 일

- **자동 배포**: `.github/workflows/deploy.yml`. `main`에 올라가면 린트·타입·테스트를 통과한 빌드를 GitHub Pages에 올린다. 하위 주소(`/lablog/`)에서 열리도록 빌드 때 `VITE_BASE`를 주고, 앱 라우터는 `import.meta.env.BASE_URL`을 기준 경로로 쓴다. 새로고침이나 직접 주소로 들어와도 열리도록 `404.html`을 `index.html`로 복사한다.
- 로컬에서 `VITE_BASE=/lablog/`로 빌드해 `/lablog/`, `/lablog/projects` 등이 열리고 메뉴 링크가 기준 경로를 따르는 것을 확인했다.
- **버전 표시**: 설정 화면 아래(이미 있음). 파일 형식 버전은 하드코딩 대신 상수를 쓰도록 고쳤다.
- **첫 사용 안내**: 빈 홈 화면에 "데이터는 이 브라우저에만 저장됩니다. 백업하세요"를 적고, "예시 데이터 넣기" 버튼을 개발 서버가 아니어도 보이게 했다.
- **사용 안내 1페이지**: `01-사용-안내.md`.

## 남은 것

- 저장소 설정 → Pages → Source를 **GitHub Actions**로 바꾼다(한 번). 그 뒤 `main`에 올라가면 배포된다.
- 무료 Pages는 보통 공개 저장소가 필요하다. 비공개로 두려면 Netlify나 Vercel로 옮긴다(빌드 명령은 같다).
- **주소가 바뀌면 기록이 안 보인다**(브라우저 저장소는 주소마다 따로). 개발 서버(`localhost`)에서 쓰던 기록은 설정에서 내보낸 뒤 배포 주소에서 가져온다.
- 건너뛴 것: PWA(기기를 정하지 않음), 주간 피드백·백업 수집·KR 평가 보고서(혼자 쓰므로 비교 대상 없음).
