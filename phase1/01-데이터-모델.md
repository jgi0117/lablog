# 데이터 모델과 규칙

코드 기준: `app/src/domain/types.ts`, `rules.ts`, `app/src/data/repositories/index.ts`
문서와 코드가 다르면 코드가 맞습니다. 바꿀 때는 이 문서도 같이 고칩니다.

## 공통 원칙

- **ID**: 클라이언트가 만드는 UUID. 로컬과 Supabase에서 같은 값을 쓴다. 호출자가 id를 줄 수 있다(데이터 이전을 다시 실행해도 중복되지 않게).
- **시각**: ISO 8601 UTC 문자열.
- **소프트 삭제**: `deletedAt`을 채운다. 30일 뒤 영구 삭제(`purgeExpired`).
- **version**: 저장할 때마다 1 증가. `expectedVersion`을 주면 동시 수정을 감지한다(`ConflictError`).
- **비동기**: 저장소 호출은 전부 Promise. 로컬도 동기로 만들지 않는다.

## 엔티티

**Project**: name, description

**Experiment**
- projectId(없을 수 있음), title(필수), purpose, owner, tags[]
- status: ready(준비) / running(진행) / done(완료)
- startedAt, completedAt
- sourceExperimentId: 복제한 실험이면 원본 ID

**Step**: experimentId, order(1부터), content, done, doneAt, note

**DataItem**: experimentId, kind(condition/result), order, name, value(문자열), unit
- 값을 문자열로 두는 이유: "—", 범위("78~82"), 단위 없는 값을 허용하기 위해. 숫자 검증은 화면에서 경고만 한다.

**Attachment (P1)**: experimentId, stepId?, fileName, mimeType, size, blobRef
**Deviation (s3)**: experimentId, stepId?, change, reason
**Template (s3)**: name, steps[], defaultConditions[]

태그는 지금 Experiment의 문자열 배열로 둔다. 병합·이름 변경이 필요해지면 별도 테이블로 분리한다.

## 규칙

- **상태 전이**: 준비 → 진행 → 완료. 완료에서 진행으로 재개 가능. 준비에서 바로 완료, 완료에서 준비로는 못 간다.
- **진행률** = 완료 단계 수 / 전체 단계 수, 정수 퍼센트. 단계가 없으면 0%.
- **완료 처리 경고(E3, E8)**: 미완료 단계 수와 빈 결과 수를 보여 준다. 막지는 않고 "나중에 입력"을 허용한다.
- **휴지통**: 삭제하면 실험과 딸린 단계·조건·결과도 함께 숨긴다. 복원하면 같이 돌아온다. 보관 30일.
- **setDone(E2)**: done과 doneAt을 함께 바꾼다. 해제하면 doneAt이 비워진다. 같은 값이면 version을 올리지 않는다.
- **복제(E8)**: 절차와 조건은 복사한다. 체크, 메모, 결과는 비운다. 상태는 준비. 원본은 바뀌지 않는다.
- **검색**: 제목, 목적, 태그, 단계, 메모, 조건, 결과를 본다. 휴지통은 제외. 일치한 위치(field, 단계 번호)를 함께 돌려준다. 띄어쓰기가 달라도 부분 일치로 찾는다.

## 저장소 인터페이스

`DataBackend` 하나가 아래를 묶는다. 화면은 이것만 부른다.

- `projects`: list, create, update, softDelete
- `experiments`: list(filter, sort, page), get, create, update, softDelete, restore, purgeExpired, search, duplicate
- `steps`: listByExperiment, create, update, remove, reorder, setDone
- `dataItems`: listByExperiment, create, update, remove
- `backup`: exportAll, importAll(merge | replace)

오류: `NotFoundError`, `ConflictError`, `StorageError`(quota, blocked, unknown)

## 로컬 DB (IndexedDB) 규칙

- 스키마 버전은 정수. 올릴 때마다 업그레이드 함수와 테스트를 같이 만든다.
- 테이블: projects, experiments, steps, dataItems (+ attachments P1)
- 인덱스: experiments(status, projectId, updatedAt), steps(experimentId, order), dataItems(experimentId, kind)
- 검색 색인은 별도 메모리 구조(MiniSearch)에 두고, 실험·단계·데이터가 바뀔 때 해당 실험만 갱신한다.
